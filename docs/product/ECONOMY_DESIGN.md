# 학급화폐/보상 정책 설계

## 1. 학급화폐 목적

학급화폐는 퀴즈 참여를 꾸준히 유도하고, 퀴즈 결과가 상점, 내 집, 아바타 꾸미기 같은 비경쟁형 활동으로 이어지게 만드는 보상 장치다.

설계 방향은 다음과 같다.

- 퀴즈 참여 동기 부여
- 상점, 내 집, 아바타 꾸미기와 연결
- 랭킹 부담이 큰 학생도 보상받을 수 있게 설계
- 정답률이 낮은 학생도 완료, 도전, 퀘스트 참여로 작은 보상을 받을 수 있게 구성
- 경쟁 보상보다 누적 성장과 꾸미기 보상에 무게를 둠

## 2. 화폐 이름 확정

| 후보 | 장점 | 단점 |
| --- | --- | --- |
| 코인 | 직관적이고 학생이 이해하기 쉬움 | 개성이 약함 |
| 하트베리 | 귀엽고 보상 느낌이 강함 | 화폐라는 의미가 바로 드러나지 않을 수 있음 |
| DJ코인 | DJ48 브랜드와 잘 연결됨 | 일반적인 코인 느낌이 강함 |
| 퀴즈코인 | 퀴즈 보상이라는 목적이 명확함 | 이름이 다소 설명적임 |

최종 화폐 이름: **DJ코인**

UI 표기:

- 정식 표기: `DJ코인`
- 짧은 표기: `코인`

확정 이유:

- DJ48 서비스명과 직접 연결된다.
- 학생과 교사가 의미를 쉽게 이해할 수 있다.
- 상점 가격, 퀘스트 보상, 랭킹전 보상에 붙였을 때 어색하지 않다.
- 화면의 여유가 있는 곳에서는 `DJ코인`, 카드 배지나 좁은 버튼에서는 `코인`으로 표기할 수 있다.

## 3. 보상 지급 기준

보상은 결과 보상과 참여 보상을 분리한다.

- 연습전 완료: 퀴즈를 끝까지 완료하면 지급
- 정답 수: 맞힌 문제 수에 따라 소량 추가 지급
- 랭킹전 참여: 경쟁 모드에 참여한 것 자체에 지급
- 원코 모드 성공: 원코 조건을 달성했을 때 지급
- 일일 퀘스트 완료: 매일 갱신되는 개인 퀘스트 완료 시 지급
- 주간 학급 미션 달성: 학급 공동 목표 달성 시 지급

권장 원칙:

- 참여 보상은 낮지만 안정적으로 지급한다.
- 성과 보상은 높게 주되 하루 상한을 둔다.
- 학급 미션 보상은 개인 간 격차보다 공동 달성 경험을 강화하는 방향으로 둔다.

## 4. 보상 예시 표

| 활동 | 보상 예시 | 비고 |
| --- | ---: | --- |
| 연습전 완료 | 5 DJ코인 | 정답 수와 무관한 완료 보상 |
| 정답 1개당 | 1 DJ코인 | 퀴즈별 최대 지급량 제한 필요 |
| 랭킹전 참여 | 10 DJ코인 | 반복 참여 제한 필요 |
| 원코 성공 | 15 DJ코인 | 성공 조건이 명확할 때만 지급 |
| 일일 퀘스트 | 10~30 DJ코인 | 난이도별 차등 지급 |
| 주간 미션 | 50~100 DJ코인 | 학급 공동 보상 또는 개인 기여 보상 검토 |

예시 계산:

- 연습전 3문제 중 2문제 정답: 완료 5 + 정답 2 = 7 DJ코인
- 일일 퀘스트까지 완료: 7 + 퀘스트 10 = 17 DJ코인

## 5. 확정 보상 정책

### 하루 획득 상한

- 기본 상한: 하루 100 DJ코인
- 교사 이벤트 보상은 예외 가능
- 상한 초과 시 안내 문구: `오늘 받을 수 있는 기본 보상을 모두 받았어요`

하루 획득 상한은 일반 퀴즈 보상, 랭킹전 참여 보상, 일반 퀘스트 보상에 적용한다. 교사가 수동으로 지급하는 특별 이벤트 보상, 오류 보정, 학급 행사 보상은 별도 예외로 둘 수 있다.

### 연습전 보상

- 완료 보상: 5 DJ코인
- 정답 1개당: 1 DJ코인
- 같은 퀴즈의 완료 보상은 하루 1회만 지급
- 정답 보상은 같은 퀴즈당 하루 최대 10문제까지만 인정

예시:

- `spelling` 연습전을 하루에 3번 완료해도 완료 보상 5 DJ코인은 1회만 지급한다.
- 같은 퀴즈에서 20문제를 풀어도 정답 보상은 최대 10문제까지만 인정한다.

### 랭킹전 보상

- 참여 보상: 10 DJ코인
- 하루 최대 3회까지만 지급
- 1위/상위권 추가 보상은 아직 보류
- 랭킹 조작 방지를 위해 실제 저장 전 서버 검증 필요

랭킹전은 보상이 과하면 반복 참여와 조작 유인이 생길 수 있다. 첫 구현에서는 순위 보상보다 참여 보상을 안정적으로 지급하고, 상위권 추가 보상은 실제 기록 검증 구조가 준비된 뒤 다시 결정한다.

### 원코 모드 보상

- 성공 보상: 15 DJ코인
- 실패 시 참여 보상 후보: 없음 또는 3 DJ코인
- 최종 추천안: 성공 보상만 지급

원코 모드는 도전형 모드이므로 성공 보상만 지급하는 방향이 적절하다. 실패 보상을 주면 반복 시도 보상이 될 수 있으므로 첫 구현에서는 제외한다.

### 퀘스트 보상

| 퀘스트 난이도/종류 | 보상 |
| --- | ---: |
| 쉬움 | 10 DJ코인 |
| 보통 | 20 DJ코인 |
| 어려움 | 30 DJ코인 |
| 주간 개인 퀘스트 | 50 DJ코인 |
| 학급 공동 미션 | 50~100 DJ코인 |

퀘스트 보상은 난이도를 명확히 구분한다. 쉬움은 매일 부담 없이 완료할 수 있는 수준, 보통은 여러 문제나 특정 과목 참여, 어려움은 여러 조건을 조합한 목표로 둔다.

## 6. 상점 가격 확정안

| 아이템 종류 | 확정 가격 기준 | 설명 |
| --- | ---: | --- |
| 작은 장식 | 50 DJ코인 | 화분, 작은 소품 |
| 일반 장식 | 100 DJ코인 | 책장, 중간 크기 방 장식 |
| 배경 | 150 DJ코인 | 내 집 배경, 타운 카드 배경 |
| 아바타 | 200 DJ코인 | 캐릭터 외형, 표정, 의상 |
| 칭호 프레임 | 250 DJ코인 | 대표 칭호를 꾸미는 프레임 |
| 희귀 아이템 | 500 DJ코인 이상 | 시즌 이벤트 또는 장기 목표 보상 |

가격 원칙:

- 첫 구매는 어렵지 않게 만든다.
- 꾸미기 핵심 아이템은 1~2주 활동으로 구매 가능하게 둔다.
- 희귀 아이템은 장기 목표로 남긴다.
- 성능 차이를 만드는 아이템은 만들지 않는다.

## 7. 인플레이션 방지 규칙

DJ코인이 너무 빠르게 쌓이면 상점 가격과 보상 가치가 무너질 수 있다.

권장 제한:

- 하루 획득 상한 설정
- 같은 퀴즈 반복 보상 제한
- 랭킹전 보상 과다 방지
- 퀘스트 보상은 하루 1회 또는 정해진 횟수만 지급
- 교사용 보정 가능성 확보

예시 규칙:

- 하루 기본 획득 상한: 100 DJ코인
- 같은 퀴즈 연습전 완료 보상: 하루 1회만 지급
- 정답 수 보상: 같은 퀴즈는 하루 최대 10문제까지만 인정
- 랭킹전 참여 보상: 하루 3회까지만 지급
- 교사 보정: 특별 수업, 행사, 오류 보정 시 수동 지급/차감 가능
- 상한 초과 안내: `오늘 받을 수 있는 기본 보상을 모두 받았어요`

## 8. 퀘스트 설계

### 일일 퀘스트

매일 가볍게 완료할 수 있는 개인 목표다.

예시:

- 맞춤법 연습전 1회 완료
- 사회 퀴즈 3문제 풀기
- 수학 연습전 도전하기
- 오늘 퀴즈 5문제 풀기

### 주간 퀘스트

며칠 동안 누적해서 달성하는 개인 목표다.

예시:

- 이번 주 국어 퀴즈 5회 완료
- 이번 주 총 30문제 풀기
- 정답 20개 모으기

### 학급 공동 미션

학급 전체의 누적 활동을 모아 달성하는 목표다.

예시:

- 우리 반 누적 퀴즈 100회 도전
- 학급 누적 DJ코인 2000개 모으기
- 이번 주 랭킹전 참여 30회

### 시즌 이벤트

기간 한정 테마와 연결한다.

예시:

- 독서왕 시즌
- 삼국시대 탐험 주간
- 계산왕 챌린지

## 9. 구현 시 필요한 상수명 제안

## 10. 운영본 DJ48과 연결할 지점

운영본과 연결할 때는 기존 퀴즈 결과를 보상 이벤트로 변환하는 지점이 핵심이다.

- 퀴즈 완료 결과
  - 완료 여부
  - 정답 수
  - quizId
  - modeId

- 랭킹전 결과
  - 참여 여부
  - 점수
  - 순위
  - 보상 지급 여부

- 타이틀/뱃지 획득
  - 특정 조건 달성 시 지급
  - 예: 독서 퀴즈 10회 완료, 삼국시대 퀴즈 정답 30개

- 상점 아이템 구매
  - 보유 DJ코인 확인
  - 구매 가능 여부 판단
  - 구매 내역 저장
  - 보유 아이템 반영

- 내 집 꾸미기
  - 보유 아이템 목록 조회
  - 적용 중인 배경, 아바타, 장식 저장

## 12. 아직 하지 않을 것

이번 단계에서는 다음 기능을 결정하거나 구현하지 않는다.

- 실제 보상 저장
- 실제 구매 처리
- 학생 간 거래
- 복권
- 은행
- 자동 벌점
- 학생 간 선물하기
- 현금성 가치와 연결되는 기능
- 보상 회수/벌점 자동화

학생 간 거래와 확률형 기능은 학급 운영 리스크가 크므로 현재 설계 범위에서 제외한다.
