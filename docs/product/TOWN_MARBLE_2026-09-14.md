# 두근두근 마블 로컬 개발 기록

작성일: 2026-09-14. 요청: 모두의마블의 경쾌한 연출을 참고한, 기본 부루마블 흐름의 학교 온라인 대전 게임.

## 구현 상태

`town-marble-src/`에서 새 게임을 개발하고 `public/town-marble/`로 빌드했다. 기존 특산물 무역 게임 `marble-src/`와 다른 게임이며, 기존 워드배틀의 미커밋 작업을 수정하지 않았다. 2026-09-15 사용자 승인으로 마블 서버·접근 규칙·화면을 운영 Firebase에 배포했다. Git commit·push는 실행하지 않았다.

- 2~4인 방 코드 대전, 전원 준비, 방장 시작, 재접속, 대기실 방장 이관 및 연결이 끊긴 자리 정리.
- 봇 3명과 연습, 네 동물 캐릭터, 게임 전 이미지 프리로드, 효과음 선택, 모션 감소.
- 주사위 2개, 토지 구매, 별장·빌딩·호텔 3단계 건설, 통행료, 월급, 황금열쇠 12종, 무인도·탈출권, 기부금·복지기금, 다음 차례 우주여행.
- 현금 부족 시 매각, 회복 불가능한 부채의 파산, 채권자에게 자산 이전, 마지막 생존자 승리.
- 기본 모드와 구분한 20/30분 총자산 모드, 공동 우승, 온라인 서버 턴 시간 초과 처리.
- 칸마다 점프, 방향 전환, 이벤트 순간이동, 건물 등장, 잔액 증감, 통행료 동전 비행.
- 노트북·태블릿·휴대폰 반응형 화면, 키보드 조작 가능한 기본 버튼, 포커스가 유지되는 모달과 Escape 닫기.

## 규칙 범위

현재 규칙명은 **DJ48 기본형 v1 · 32칸**이다. 상용 판본 설명서를 확보하거나 특정 판본을 사용자에게 지정받은 상태는 아니다. 따라서 상용 부루마불 전체 규칙의 정확한 복제라고 표시하지 않는다. 게임 내 규칙 설명도 이 범위를 명시한다.

도시 배치·가격·카드 텍스트는 독자 구성이다. 시작 현금 200만, 월급 20만. 내 땅에 도착한 차례에 건물을 순차적으로 올리며, 매각은 땅 구매가와 누적 건설비 합계의 절반을 정수로 버림 처리한다. 경매·개인 간 거래·담보대출·상용판 특수 운송수단·독점 승리·캐릭터 능력은 포함하지 않는다. 특정 판본을 정확히 재현하는 작업은 이 독립 규칙표와 구분해야 한다.

## 통신과 화면

사용자의 “모두의마블 같은 큰 애니메이션” 피드백을 반영해 2.5D 버전을 실제 Three.js 3D 장면으로 교체했다. React는 플레이어 HUD·메뉴·선택 UI만 관리한다. 게임판과 캐릭터·건물·연못·성·풍차는 실제 입체 모델이며 카메라 회전·확대가 가능하다.

- 동물 4종은 머리·팔·다리가 분리되어 걷기·점프·방향 전환·축하 동작을 한다. 토끼 귀의 관절과 눈 깜빡임도 별도로 움직인다.
- 주사위는 6면 숫자 텍스처를 가진 입체 큐브이며, 서버 확정값으로 회전을 마친 뒤 캐릭터가 이동한다. 카메라 추적·확대, 순간이동 포물선, 착지 파티클을 기기 안에서 재생한다.
- 구매·건설 시 건물이 내려와 튀어 오르는 연출과 축하 배너를 표시한다. 황금열쇠는 큰 카드가 뒤집히며 등장한다. 메뉴는 양쪽 플레이어 정보와 하단 조작창으로 바꿨다.
- 생성한 파노라마 하늘을 전체 배경에 사용한다. 생성 초상화는 HUD에 유지하고, 입체 화면의 모델은 코드로 만든다. 이전 섬·건물 아틀라스는 WebGL 불가 또는 컨텍스트 손실 시의 대체 화면에 사용한다.
- 정적 모델은 재질별로 병합하고 geometry/material을 공유한다. 정적 그림자는 건설 변경 시 갱신하고 이동하는 캐릭터는 별도 접지 그림자를 사용한다. DPR 상한 1.5, 저성능 기기 자동/수동 30fps·DPR 1·그림자와 파티클 감소, 모션 감소를 제공한다.
- 3D 엔진은 별도 청크로 지연 로딩한다. 일반 초기 화면은 새 하늘·초상화 약 3.10MB와 코드/스타일을 읽는다. 이미지가 매 턴 다시 전송되지는 않는다.

온라인은 Node + WebSocket의 권위 서버 방식이다. 주사위와 카드의 난수는 서버의 `crypto.randomInt`가 생성하며, 브라우저가 보낸 돈·주사위 값은 채택하지 않는다. 규칙 엔진은 연습 모드와 공유한다. 방 상태의 버전과 요청 ID를 검증해 오래된 선택과 중복 처리, 다른 플레이어의 차례 조작을 막는다.

통신은 선택 결과와 접속 상태가 바뀔 때만 방 단위 스냅샷을 보낸다. 프레임별 좌표 전송은 없고, 캐릭터 경로와 서버 확정 결과를 기기가 재생한다. 느린 기기의 애니메이션 완료를 서버가 기다리지 않는다. 로그 길이·대기 요청·소켓 버퍼·메시지 크기·접속 수에 제한을 두었다. 참가 토큰은 URL과 다른 참가자의 스냅샷에 넣지 않는다.

## 검증

2026-09-14 3D 개편 후 규칙/방/네트워크 17개 검사, 4인 Chrome 스모크, 저장소 전체 `npm run check`를 통과했다. 3D 카메라 회전, 실제 이름표 좌표 이동, 3단계 호텔, 황금열쇠 연출도 검증한다. WebGL 컨텍스트 손실 시 대체 화면에서 같은 게임을 유지하는 검사를 추가했다.

단일 macOS headless Chrome 1366×900에서 측정한 180프레임의 중앙값·p95는 약 16.7ms였다. 이 측정은 학생 기기나 Wi-Fi 성능 검증이 아니며, GPU·탭 수에 따라 달라진다. 동영상 녹화도 실제 플레이 화면에서 수행한다. [플레이 영상](town-marble-art/V2_GAMEPLAY_2026-09-14.webm), [게임 화면](town-marble-art/V2_GAMEPLAY_2026-09-14.png), [측정 환경과 결과](town-marble-art/V2_METRICS_2026-09-14.json)를 함께 보관한다. 화면 캡처 테스트의 고정 난수는 격리된 서버 안에서만 사용한다.

- 규칙·방 테스트 및 100판의 2/3/4인 봇 경기에서 음수 잔액, 파산자 소유권, 잘못된 현재 플레이어, 미종료 경기 여부를 확인했다.
- 실제 WebSocket 32접속·8개 방을 생성하고 격리, 동기화, 권한, 연결 복구를 확인했다. 초기 측정 24개 행동의 loopback p95 응답은 약 0.60ms였다. **같은 컴퓨터 안의 측정이며 학교 Wi-Fi나 공개 서버의 지연 수치가 아니다.**
- Chrome 네 브라우저 컨텍스트로 방 참가·준비·시작, 실제 이동 애니메이션, 구매·건설, 새로고침 복구를 확인했다.
- 1366×900, 1024×768, 390×844 화면을 확인하고 휴대폰에서 발견한 가로 넘침을 수정했다.
- 기존 저장소 `npm run check` 전체 통과. 새 게임은 별도 `npm run check:town-marble`로 검사한다.
- 새 게임 종속성은 Vite 8 계열로 갱신했으며 설치 시 `npm audit` 보고 취약점 0건이었다.

## 운영 연결 및 후속 확인

최초 WebSocket 개발 서버는 단일 프로세스·메모리 저장이다. 후속 요청으로 Firebase 영속 온라인 경로와 퀴즈타운 메뉴·랭킹을 구현했다. 운영 반영 전 검증과 적용 범위는 `../operations/TOWN_MARBLE_ONLINE_2026-09-14.md`가 정본이다.

1. 2026-09-15 사용자 승인으로 Firebase Hosting + `townMarbleAction` + 마블 전용 Rules의 운영 반영을 완료했다. 당시 운영본을 기준으로 마블 변경만 추가했다.
2. 운영 적용 뒤 활성 계정의 참가·재접속·랭킹 읽기와 함수 로그를 확인한다. 현재 검증은 합성 계정과 로컬 에뮬레이터에서 수행했다.
3. 실제 학교 Wi-Fi와 학생용 기기에서 32명 동시 이미지 로딩, 프레임 시간, 입력 확정 지연 p95/p99, 접속 손실·복구를 측정한다. 요청한 무지연은 아직 검증되지 않았으며 절대 보장하지 않는다.
4. 기준 판본과 수업 길이에 맞춰 규칙·가격·게임 길이를 사용자 플레이테스트로 조정한다.
5. 배포 이후에도 commit·push·운영 학생 데이터 직접 수정은 수행하지 않았다. 상세 배포 결과는 운영 보고서에서 확인한다.

## 도시명과 UI 겹침 보완 — 2026-09-14 후속

- 32개 흰색 도시 이름표를 제거했다. 보드 바깥 전용 띠에 실제 평면 텍스처로 도시명을 인쇄하고, 카메라 방향에 맞춰 글자 방향을 반전한다. 가격·소유자·건설 단계는 보드의 도시를 누르거나 ‘도시 목록’에서 확인한다.
- 도시명, 건물/이동 공간을 물리적으로 분리하고, 같은 칸의 동물들은 작은 크기로 화면 수평 방향에 나란히 배치한다. 머리 위의 중복 이름표는 표시하지 않는다. 이동 중의 캐릭터는 크게 표현한다.
- 게임판, 플레이어 정보, 카메라 도구, 하단 조작창을 서로 다른 CSS Grid 영역에 배치한다. 데스크톱 이벤트 안내는 오른쪽 빈 영역, 좁은 화면에서는 도구줄과 같은 전용 영역을 번갈아 사용한다. 선택/구매 버튼과 안내문, 턴 정보도 겹치지 않는 내부 행·열을 사용한다.
- 금액 증감 숫자가 플레이어 이름을 가리지 않도록 잔액 옆의 작은 글씨로 변경했다. 세로 태블릿은 플레이어 네 명을 상단 한 줄에 배치하고 게임판에 전체 너비를 제공한다.
- 새 `npm run smoke:layout`은 1440×960, 1366×768, 1024×768, 768×1024, 390×844, 360×740에서 기본 화면·이동·건설·카메라 네 방향·확대 등 총 54개 상태를 검사한다. UI 사각형 교차뿐 아니라 도시명 평면의 실제 투영 다각형도 검사한다. 명시적으로 여는 상세 모달은 이 비겹침 기준의 대상이 아니다.
- 게임 규칙과 서버 통신 방식은 변경하지 않았다. 운영 배포와 학생 데이터 변경은 하지 않았다.
