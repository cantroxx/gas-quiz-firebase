# 자체 아바타·하우징 + 상점 체험판

## 열기

프로젝트 루트에서 `python3 -m http.server 5328 --bind 127.0.0.1 --directory public` 실행 후 <http://127.0.0.1:5328/cozy-home-preview/> 접속.

`public/cozy-home-preview/`에 분리한 프로토타입이다. 기존 하우징·상점 메뉴에 연결하거나 운영 배포하지 않았다. Firebase SDK와 Habbo 이미지 서버에 접근하지 않는다. 기록은 이 브라우저의 `quiztown-original-home-prototype-v1` localStorage에만 저장된다.

## 체험 기능

- 토끼·고양이·곰, 털 4색, 옷 4색, 조끼·줄무늬 티·멜빵 바지, 베레모·꽃핀.
- 캐릭터 앞·뒤 방향 표현, 클릭·키보드 이동, 가구를 피해 이동, 의자에 앉기·일어나기.
- 방 8×8칸, 벽 3색, 방 이름 변경.
- 가구 6종: 침대·책상·의자·책장·화분·러그.
- 가구 1개씩 기본 지급 + 체험 코인 300. 추가 구매·보관·배치·이동·회전·취소.
- 방 밖·가구 겹침·캐릭터 위치 배치 방지. 러그 위에 다른 가구 배치 허용.
- 보유 가구·배치·캐릭터 외형·벽색·방 이름·체험 코인 저장/복원. 재접속 시 캐릭터 위치는 빈칸에서 시작.
- PC·모바일, 키보드, 움직임 줄이기 설정, 저장 공간 사용 불가 안내.

## 자체 제작 방식과 한계

가구는 built-in image_gen으로 만든 투명 3×2 아틀라스다. [가구 이미지](../../public/cozy-home-preview/assets/furniture-atlas.png)와 [최종 생성 프롬프트](ORIGINAL_HOUSING_IMAGE_PROMPT_2026-09-16.json)를 저장했다. 방·캐릭터는 자체 Canvas 도형과 레이어로 그린다. 기존 Habbo 자산·파츠 번호를 사용하지 않는다.

첫 번째 조작 검증용으로 캐릭터 동작은 단순한 팔다리 움직임이며, 정교한 방향별 스프라이트는 아니다. 가구 방향은 두 방향의 좌우 반전으로 표현한다. 뒷면까지 포함한 4방향 회전, 여러 가구 쌓기·벽걸이, 침대 눕기, 친구 방문·실시간 동접은 포함하지 않는다. 가구와 캐릭터의 묘사 밀도는 후속 아트 작업에서 더 통일할 수 있다.

## 검증

`node scripts/smoke/cozy-home-preview-browser.js` 통과: 구매 금액/보유량, 잔액 부족, 충돌·방 밖 배치 거부, 회전·보관·이동 취소, 의자 접근 경로·앉기·일어나기, 외형 변경, 저장/복원, 모바일 가로 탐색, 키보드, 움직임 줄이기, 저장 실패, 운영/Habbo 요청 없음. 정적 검사 통과.

## 실제 상점 연결 전에

1. 캐릭터·방의 아트 방향을 사용자 검토로 확정한다.
2. 기존 `userInventory`·`userEconomy` 구매 검증에 자체 item ID를 연결하고 실제 상품 가격을 정한다. 체험 가격은 운영 가격이 아니다.
3. 기존 `userHomeRooms`는 문서 전체 교체 저장이므로 별도 버전/저장 경로를 설계하고 권한·복구 검증 후 연결한다. 기존 방을 덮어쓰지 않는다.
4. 기존 구매 가구 보존·교환 정책을 정하고 새 가구 대응표를 준비한다.
5. 실제 학교 기기에서 조작과 성능을 확인한 뒤 선택적으로 운영 진입점을 연결한다.
