# 교실 UI/기능 재편 지침

## 1. 목표

DJ48 교실 UI를 기능 추가 순서가 아니라 사용 흐름 기준으로 재편한다. 이 문서는 이후 교실 UI 작업의 기준 문서이며, 단순 제안서가 아니라 구현 판단 규칙으로 사용한다.

핵심 목표는 다음과 같다.

- 학생 화면은 오늘 할 일과 내 상태를 빠르게 확인하는 낮은 밀도 UI로 만든다.
- 교사 화면은 기능별 관리 화면으로 나누고, `교사 작업대`에 모든 설정을 몰아넣지 않는다.
- 검토, 승인, 요청처럼 행 단위 처리가 필요한 데이터는 카드보다 표를 우선한다.
- 퀘스트, 성장루틴, 젬스톤, 직업, 마켓, 은행, 학급미션은 독립 기능으로 다룬다.
- 기존 Firestore 컬렉션과 callable 계약은 유지하고, 우선 DOM/렌더링 재배치로 시작한다.

근거 문서:

- `docs/product/grownd-classroom-ui-scan.md`
- `docs/product/dj48-classroom-feature-reclassification.md`

## 2. Grownd 관찰 요약

Grownd는 교사와 학생 화면의 역할이 명확히 다르다.

교사 화면의 주요 관찰:

- 교사 홈은 학급과 학생카드를 중심으로 한다.
- 기능 관리는 `교사 작업대` 하나에 몰려 있지 않고 기능별 페이지로 분리된다.
- 퀘스트 관리는 별도 페이지이며, 상단 요약, 카테고리, 검색, 정렬, 노출 필터, 추가/아카이브 액션을 가진다.
- 성장루틴은 학생 목록과 선택 학생 상세를 나누고, `진행중`, `마감 검토`, `처리 완료` 상태를 분리한다.
- 학급미션은 현재 학급 포인트, 다음 목표, 진행률, 새 미션 추가, 등록된 미션 목록을 한 페이지에 둔다.
- 학급 자산 현황은 탭 구조를 사용한다. `학급 자산 정보`, `포인트 요청`, `일별`, `월별`, `학생별` 현황이 분리된다.
- 학생 관리는 테이블 중심이다. 아바타, 번호, 이름, 비밀번호, 관리 액션이 행 단위로 정리된다.

학생 화면의 주요 관찰:

- 상단 탭은 `카드`, `텃밭 은행`, `마켓`, `젬스톤`, `직업`처럼 학생이 이해하기 쉬운 경험 단위다.
- 우측 활동 패널은 `클래스 알림`, `퀘스트`, `성장 루틴`, `우리반 미션`, `웍스`를 지속적으로 보여준다.
- 퀘스트와 성장루틴 상세는 모달로 열리며, 학생에게 필요한 상태와 행동만 보여준다.
- 학생 은행, 마켓, 젬스톤, 직업 화면은 설정 폼이 아니라 내 상태와 다음 행동 중심이다.

DJ48에 적용할 핵심 해석:

- 교사용 설정 기능은 기능별 관리 화면으로 이동한다.
- 학생 화면은 경험 탭과 오늘 할 일 중심으로 정리한다.
- 교사 작업대는 작업대가 아니라 처리 큐가 되어야 한다.

## 3. 우리 교실 기능 재분류

현재 DJ48 교실의 문제는 기능이 없는 것이 아니라 기능의 위치가 섞인 것이다.

현재 구조:

- 상단 탭: `대시보드`, `학생카드`, `젬스톤`, `직업`, `마켓`, `교사 작업대`
- 학생카드 하위 탭: `교실 퀘스트`, `성장루틴`, `학급 미션`, `학급 은행`
- 교사 작업대 내부: 퀘스트, 월간 키링, 미션, 세금, 직업, 상점, 공동구매, 적금, 환전, 젬스톤, 알림, 검토 처리

재분류 기준:

- `홈`: 오늘 할 일, 내 카드 요약, 최근 활동, 포인트/코인 요약
- `학생카드`: 학생 카드 무대, 카드 표시, 대표 정보, 포인트 조정
- `퀘스트`: 학생 활동, 완료 상태, 교사 CRUD, 검토
- `성장루틴`: 학생 습관 체크, 교사 기간 종료 검토, 보상 부여
- `젬스톤`: 학생 성장 단계, 교사 젬 설정, 학생별 진행도
- `직업`: 학생 지원/월급, 교사 직업 관리/배정/급여 처리
- `마켓`: 학생 구매/사용/장착, 교사 상품/공동구매/요청 관리
- `은행`: 학생 환전/적금, 교사 경제 설정/자산/요청/세금 관리
- `학급미션`: 학생 공동 목표 확인, 교사 목표/보상 설정과 정산
- `알림`: 학생 공지 확인, 교사 알림 슬롯 편집
- `학생관리`: 교사용 학생 표시/비밀번호/테스트 학생/리포트 관리
- `처리할 일`: 교사용 검토 대기와 요청 처리 큐

`교사 작업대`는 이름과 역할을 바꾼다.

- 기존 이름: `교사 작업대`
- 새 이름: `처리할 일`
- 남길 것: 검토 대기, 요청, 최근 활동, 비정상 상태 알림
- 뺄 것: 모든 생성/수정/삭제/장기 설정 폼

## 4. 학생 화면 원칙

학생 화면은 기능을 많이 보여주는 곳이 아니라 학생이 오늘 무엇을 하면 되는지 알려주는 곳이다.

학생 홈에 둔다:

- 내 카드 요약
- 오늘 퀘스트
- 성장루틴 상태
- 학급미션 진행률
- 내 포인트와 DJ코인
- 현재 직업
- 대표 젬/키링
- 최근 받은 보상

학생 홈에서 제외한다:

- 교사용 설정 폼
- 전체 학생 관리
- 관리자 로그
- 긴 설명 문단
- 전체 경제 설정
- 전체 퀘스트 관리 도구

학생 기능 화면 규칙:

- `퀘스트`: 오늘 할 퀘스트와 완료 버튼만 우선 노출한다.
- `성장루틴`: 진행중, 검토중, 완료 상태를 나누고, 새 루틴 추가와 수정 동선을 유지한다.
- `젬스톤`: 내 성장 단계, 다음 단계까지 남은 횟수, 대표 키링 설정을 보여준다.
- `직업`: 내 직업, 지원 가능한 직업, 지원 상태, 월급 상태를 보여준다.
- `마켓`: 포인트샵, 코인샵, 공동구매, 인벤토리 중심으로 보여준다.
- `은행`: 내 포인트, DJ코인, 환전, 적금, 만기 수령만 보여준다.
- `학급미션`: 현재 목표, 다음 보상, 진행률을 보여준다.

학생 빈 상태 문구는 짧게 쓴다.

- 좋은 예: `오늘은 퀘스트가 없습니다.`
- 좋은 예: `아직 등록된 루틴이 없습니다.`
- 피할 것: 기능 설명을 여러 줄로 길게 늘어놓기

## 5. 교사 화면 원칙

교사 화면은 기능별 관리와 검토 처리를 분리한다.

교사용 기능 페이지 공통 골격:

- 페이지 제목
- 한 문장 설명
- 요약 지표 카드
- 필터/검색/정렬/상태칩
- 주요 액션 버튼
- 카드 또는 테이블 목록
- 생성/수정 폼 또는 모달

교사 `처리할 일`에 둘 항목:

- 퀘스트 검토 대기
- 성장루틴 검토 대기
- 마켓 사용 요청
- 공동구매/상점 요청
- 직업 지원 요청
- 최근 활동
- 오류 또는 비정상 상태

기능별 관리 화면으로 옮길 항목:

- 퀘스트 생성/수정/삭제
- 성장루틴 템플릿/보상 기준 관리
- 젬스톤 생성/수정/삭제
- 월간 키링 지급
- 직업 생성/수정/삭제
- 상품 생성/수정/삭제
- 공동구매 생성/수정/삭제
- 환전/적금/세금 설정
- 학급미션 생성/수정/삭제
- 학급 알림 편집
- 학생 계정/숨김/비밀번호/테스트 학생 관리

교사 화면에서 표를 우선할 항목:

- 퀘스트 검토
- 성장루틴 검토
- 포인트 요청
- 상점 사용 요청
- 직업 지원
- 학생별 젬스톤 진행도
- 학생별 포인트/코인 현황
- 학생관리

## 6. 탭/메뉴 구조

### 6.1 1차 목표 탭

상단 탭은 우선 다음 순서로 재편한다.

1. 홈
2. 학생카드
3. 퀘스트
4. 성장루틴
5. 젬스톤
6. 직업
7. 마켓
8. 은행
9. 학급미션
10. 처리할 일

교사 전용으로 추가할 수 있는 탭:

- 학생관리
- 알림

### 6.2 학생 표시 규칙

학생에게 기본 노출:

- 홈
- 학생카드
- 퀘스트
- 성장루틴
- 젬스톤
- 직업
- 마켓
- 은행
- 학급미션

학생에게 숨김:

- 처리할 일
- 학생관리
- 알림 관리
- 기능별 교사 관리 탭

### 6.3 교사 표시 규칙

교사에게 노출:

- 전체 학생용 탭
- 처리할 일
- 기능별 교사 관리 섹션
- 학생관리
- 알림 관리

교사에게도 홈은 학생용 홈과 완전히 같지 않아야 한다. 교사는 학급 요약, 처리할 일, 기능 바로가기를 더 우선해서 본다.

### 6.4 좁은 화면 묶음

모바일이나 탭이 너무 많아지는 화면에서는 다음 묶음을 허용한다.

- 홈
- 카드
- 할 일
- 보상
- 경제
- 관리

묶음 의미:

- `할 일`: 퀘스트, 성장루틴, 학급미션
- `보상`: 젬스톤, 직업
- `경제`: 마켓, 은행
- `관리`: 교사 전용 처리할 일, 학생관리, 알림

## 7. 카드/버튼/모달/상태칩 규칙

### 7.1 카드

카드를 쓸 곳:

- 학생카드
- 학생 홈 요약
- 학생 젬스톤
- 학생 직업
- 학생 마켓 상품
- 학생 학급미션
- 퀘스트 목록
- 요약 지표

카드를 피할 곳:

- 긴 검토 대기 목록
- 포인트 요청 목록
- 학생관리
- 학생별 젬스톤 진행도
- 경제 내역

카드 기본 구성:

- 상태칩
- 제목
- 짧은 설명
- 핵심 수치
- 다음 행동 버튼 1개
- 보조 정보는 토글 또는 상세 영역

### 7.2 버튼

버튼 규칙:

- 카드의 기본 버튼은 1개를 우선한다.
- 수정/삭제/숨김 같은 관리 액션은 교사용 관리 영역이나 더보기 안에 둔다.
- 학생 버튼 문구는 행동 중심으로 쓴다.
- 교사 버튼 문구는 처리 결과가 명확해야 한다.

좋은 버튼 문구:

- 완료하기
- 대표 키링으로 설정
- 지원하기
- 구매하기
- 검토 승인
- 반려
- 저장
- 수정
- 삭제

피할 버튼 문구:

- 처리
- 관리
- 실행
- 적용

단, 상위 관리 섹션명으로는 `관리`를 사용할 수 있다.

### 7.3 모달

모달을 쓸 곳:

- 학생 퀘스트 상세
- 학생 성장루틴 상세
- 학생 포인트/환전 입력
- 짧은 확인/완료
- 단일 생성/수정 폼

모달을 피할 곳:

- 긴 테이블 검토
- 여러 학생을 비교해야 하는 화면
- 경제 대시보드
- 학생관리

모달 기본 구성:

- 제목
- 한 문장 설명
- 본문
- 기본 버튼
- 취소/닫기

브라우저 기본 prompt/alert는 사용하지 않는다. 교실 UI와 맞는 자체 모달 또는 인라인 입력을 사용한다.

### 7.4 상태칩

상태칩은 짧고 일관되게 쓴다.

추천 상태:

- 진행중
- 검토중
- 완료
- 반려
- 대기
- 노출
- 숨김
- 시작 전
- 성장 중
- 최고 단계

상태칩은 긴 문장 대신 명사형/짧은 형용사형으로 쓴다.

## 8. 기능별 화면 배치

### 홈

학생:

- 내 카드 요약
- 오늘 할 일
- 포인트/코인
- 대표 젬/직업
- 학급미션 진행률

교사:

- 학급 요약
- 오늘 처리할 일
- 최근 활동
- 기능 바로가기

### 학생카드

공통:

- 학생 아바타
- 번호
- 닉네임
- 레벨
- 타이틀
- 포인트
- DJ코인
- 대표 키링

교사:

- 포인트 조정
- 간단 상태 확인

학생관리로 이동:

- 비밀번호
- 숨김/표시
- 테스트 학생 설정
- 리포트

### 퀘스트

학생:

- 오늘 퀘스트
- 완료 상태
- 보상
- 완료 버튼

교사:

- 퀘스트 추가/수정/삭제
- 카테고리
- 대상 학생
- 연결 젬
- 노출 상태
- 검토 대기

### 성장루틴

학생:

- 루틴 추가
- 루틴 수정

## 9. 작업 우선순위

### Phase 1. 이름과 역할 먼저 정리

목표:

- `대시보드`를 `홈`으로 바꾼다.
- `교사 작업대`를 `처리할 일`로 바꾼다.
- 처리할 일 설명을 검토/요청/최근 활동 중심으로 바꾼다.
- 데이터 구조는 바꾸지 않는다.

검증:

- 학생은 처리할 일을 볼 수 없다.
- 교사는 처리할 일을 볼 수 있다.
- 기존 퀘스트/마켓/직업/젬스톤 동작이 깨지지 않는다.

### Phase 2. 숨은 기능을 상위 탭으로 승격

목표:

- 학생카드 하위의 `교실 퀘스트`, `성장루틴`, `학급 미션`, `학급 은행`을 상위 기능으로 올린다.

추가할 탭:

- 퀘스트
- 성장루틴
- 은행
- 학급미션

주의:

- 이 단계에서는 DOM 컨테이너 이동과 탭 연결만 우선한다.
- Firestore 경로, callable, 저장 로직은 바꾸지 않는다.
- 기존 렌더 함수 재사용을 우선한다.

### Phase 3. 교사용 CRUD 폼 이동

목표:

- 교사 작업대에 몰린 폼을 기능별 관리 섹션으로 옮긴다.

이동:

- 퀘스트 만들기 -> 퀘스트
- 젬스톤 만들기 -> 젬스톤
- 직업 만들기 -> 직업
- 상점 상품 만들기 -> 마켓
- 공동구매 만들기 -> 마켓
- 환전 은행 설정 -> 은행
- 적금 상품 만들기 -> 은행
- 세금 프리셋 -> 은행
- 학급 미션 -> 학급미션
- 학급 알림 -> 알림 또는 홈 관리
- 월간 키링 지급 -> 젬스톤

### Phase 4. 검토성 데이터 테이블화

목표:

- 승인/반려/완료가 필요한 데이터는 표로 정리한다.

대상:

- 퀘스트 검토
- 성장루틴 검토
- 마켓 요청
- 직업 지원
- 포인트 요청
- 학생별 젬스톤 진행도
- 학생관리

### Phase 5. 학생 화면 단순화

목표:

- 학생 화면에서 교사용 표현을 제거하고, 오늘 행동 중심으로 정리한다.

작업:

- 홈 활동 목록 정리
- 퀘스트 상세 모달/패널 정리
- 성장루틴 상세 모달/패널 정리
- 학급미션 상태 카드 정리
- 은행/마켓/젬스톤/직업을 학생 경험 화면으로 정리

## 10. 금지 사항

아래는 특별한 사용자 승인 없이 하지 않는다.

- UI 재분류를 위해 새 Firestore 컬렉션을 만들지 않는다.
- 기존 callable 계약을 먼저 바꾸지 않는다.
- 한 번에 전체 교실 DOM을 갈아엎지 않는다.
- 교사 작업대에 새 CRUD 폼을 추가하지 않는다.
- 학생 화면에 교사용 설정 폼을 노출하지 않는다.
- 긴 검토 대기 목록을 카드로만 처리하지 않는다.
- 은행/경제 설정을 마켓 아래에 넣지 않는다.
- 젬스톤 생성 기능을 퀘스트 아래에 넣지 않는다.
- 학생 계정/비밀번호/숨김 관리를 학생카드에 계속 늘리지 않는다.
- 브라우저 기본 prompt/alert로 포인트, 환전, 조정 입력을 받지 않는다.
- 기능 위치를 바꾸면서 보상, 랭킹, 퀴즈, 계정 로직까지 동시에 수정하지 않는다.

## 11. 검증 체크리스트

### 공통

- `npm run check`가 통과해야 한다.
- 교실 진입 후 콘솔 오류가 없어야 한다.
- 학생과 교사 계정 모두 교실에 들어갈 수 있어야 한다.
- `4-8-23` 테스트 학생 숨김 정책이 깨지지 않아야 한다.
- `9-9-99` 관리자 권한 정책이 깨지지 않아야 한다.

### 학생 화면

- 학생은 교사용 처리할 일 탭을 볼 수 없어야 한다.
- 학생은 교사용 생성/수정/삭제 폼을 볼 수 없어야 한다.
- 학생은 홈에서 오늘 할 일을 확인할 수 있어야 한다.
- 학생은 퀘스트 완료, 루틴 체크, 젬 확인, 직업 지원, 마켓 구매, 은행 환전/적금을 사용할 수 있어야 한다.
- 빈 상태가 짧고 명확해야 한다.

### 교사 화면

- 교사는 처리할 일에서 검토/요청/최근 활동을 볼 수 있어야 한다.
- 교사는 기능별 화면에서 생성/수정/삭제를 찾을 수 있어야 한다.
- 퀘스트, 성장루틴, 젬스톤, 직업, 마켓, 은행, 학급미션 관리 위치가 섞이지 않아야 한다.
- 검토성 데이터는 학생 이름/번호/상태/처리 버튼이 명확해야 한다.

### 기능별

- 퀘스트: 오늘 노출, 완료 상태, 검토 대기, 연결 젬이 정상 표시되어야 한다.
- 성장루틴: 진행중, 검토중, 완료 상태가 분리되어야 한다.
- 젬스톤: 전체 젬 목록과 학생별 성장 단계가 정상 표시되어야 한다.
- 직업: 지원, 승인, 배정, 월급 흐름이 유지되어야 한다.
- 마켓: 구매, 사용, 장착, 공동구매 흐름이 유지되어야 한다.
- 은행: 환전, 적금, 만기, 세금/환율 설정 위치가 명확해야 한다.
- 학급미션: 현재 포인트, 다음 목표, 보상, 진행률이 표시되어야 한다.

### 배포 전

- 운영에 영향을 주는 변경은 `npm run check` 또는 동등한 browser smoke를 통과해야 한다.
- 배포가 필요한 경우 사용자 요청 후 `firebase deploy`를 실행한다.
- 배포 후 `https://dj48-quiztown-firebase.web.app` 응답과 smoke를 확인한다.

## Implementation Note

첫 구현 배치는 작게 간다.

1. `대시보드` -> `홈`
2. `교사 작업대` -> `처리할 일`
3. `퀘스트`, `성장루틴`, `은행`, `학급미션` 상위 탭 추가
4. 기존 렌더 함수와 데이터 흐름 유지
5. 이후 각 기능의 교사용 CRUD를 하나씩 이동

이 순서를 지키면 화면 구조는 즉시 좋아지고, 데이터/보상/권한 로직의 위험은 낮게 유지할 수 있다.
