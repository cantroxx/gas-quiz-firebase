## 실제 변경

- 밝은 중립 바탕, 흰 종이 면, 짙은 본문과 제한된 초록 강조로 공통 규칙을 정리했다. 기본 모서리 12px, 버튼 8px, 간격 16px, 조작 영역 최소 44px다. 본문은 일반 글꼴을 사용하고 장식 글꼴은 홈의 짧은 인사말에 제한했다.
- 큰 상단 장식과 반복 소제목을 줄이고 상위 메뉴/하위 탭을 구분했다. 퀘스트 통계는 작은 한 줄 정보로 바꾸고, 퀘스트는 제목·할 일·보상·상태·행동이 보이는 행으로 압축했다. 교사는 등록·관리/검토 바로가기를 사용한다. 기존 데이터에 있는 기간만 표시한다.
- 마켓에서 이미지·상품명·가격·구매 가능 상태를 목록에서 비교한다. 상세는 설명·잔액·구매 후 잔액·행동을 담고 큰 이미지를 반복하지 않는다. 모바일 상세는 선택한 상품 행 다음에 열리며, 목록으로/Escape로 닫으면 원래 상품 버튼에 포커스가 돌아간다.
- 홈, 성장루틴, 젬, 학생 카드, 직업, 은행, 우리반 목표, 교사 검토 화면에도 같은 표면·간격·타이포그래피 규칙을 적용했다. 빈 결과, 이미지 오류, 로딩·오류·비활성 상태와 포커스 표시를 정리했다. 동작 줄이기 설정을 존중한다.
- 가격은 누락/공백/비정상 값과 명시적 0을 구분한다. 누락은 “가격 미등록”, 0은 “0 P / 0원 등록 · 구매 준비 중”으로 표시한다. 기존 UI의 0 이하 구매 차단과 서버의 최소 1 가격 규칙을 유지했다. 0을 무료 상품으로 새로 허용하지 않았다.

## 생성·적용 이미지

내장 imagegen 도구로 간식, 급식 식판, 활동 노트, 빈 정리함의 네 이미지를 직접 생성했다. 절제된 색상, 어두운 윤곽, 종이 질감, 비슷한 시점의 2D 그림이다. 이미지 안의 글자·가격·버튼 및 실제 학생 정보를 사용하지 않았다.

- `public/images/classroom/stationery/{snack,lunch,notebook,empty}-{160,320}.webp`
- 간식/급식 상품은 이름의 의미에 맞는 이미지, 일반 활동은 노트, 빈 화면/알 수 없는 상품은 정리함을 사용한다. 책·자리·음악·칭찬 등은 기존 의미별 SVG를 유지한다.
- 관리자가 등록한 상품 이미지가 우선이며, 로드 실패하면 의미별 그림으로 대체한다. 대체 그림도 실패하면 “이미지 준비 중”을 표시한다.
- 기존 홈 삽화는 `public/images/classroom/{reading-sprout,community-tree}-320.webp`로 최적화했다. 원본 PNG는 보존했다.
- 생성 프롬프트: [classroom-stationery-prompts-2026-10-07.json](../product/classroom-stationery-prompts-2026-10-07.json)
- 크기·용량 명세: [classroom-stationery-assets-2026-10-07.json](../product/classroom-stationery-assets-2026-10-07.json)
- 변환 스크립트: `scripts/maintenance/optimize-classroom-art.js`. 이 머신의 생성 원본과 sharp 런타임을 사용한다. 웹 서비스에는 최적화된 WebP만 필요하다.

생성 이미지 8개 변형은 합계 72,802바이트이고, 개별 파일은 3,854~20,520바이트다. 기존 홈 삽화 2개는 합계 3,428,615 → 42,630바이트로 98.76% 줄었다. 이미지 크기/비율, async decode, 1x/2x srcset을 지정하고 비활성·아래쪽 이미지는 지연 로드한다. 처음 표시되는 핵심 상품 그림은 eager로 처리한다.

## 성능 근거와 측정

상품 선택 때 전체 상품의 클래스/버튼을 다시 바꾸던 처리를 이전·현재 상품만 갱신하도록 수정했다. 상품 ID를 Map으로 조회하고 원래 구매/수정 버튼을 이동해 이벤트 위임을 유지한다. 화면 밖 상품에는 content-visibility를 적용했다. 반응형 상세 위치를 조정하는 미디어 쿼리 리스너는 재렌더 전에 AbortController로 해제한다.

기존 로딩 계층의 요청 공유·갱신 병합을 유지했다. 교실 화면에서 추가 실시간 구독을 만들지 않았다. 교실 모듈에는 onSnapshot 구독이 없고 기존 컨트롤러 바인딩은 앱 시작 경로에서 수행된다.

`scripts/smoke/classroom-profile.js`와 오프라인 UI 하네스로, 합성 학생 24명/퀘스트 12개/상품 60개, Chromium 1440×1000, CPU 4배 제한 조건에서 변경 전→후를 순서대로 3쌍 측정했다. 각 실행은 전체 렌더 20회(준비 3회 제외), 탭 전환 40회, 상품 선택 40회, 스크롤 20회다. 아래는 **각 실행 중앙값 3개의 중앙값**이다.

| 항목 | 변경 전 | 변경 후 | 해석 |
| --- | ---: | ---: | --- |
| 전체 화면 재렌더 JS+강제 레이아웃 | 32.2ms | 35.6ms | 10.6% 증가, 개선으로 주장하지 않음 |
| 퀘스트↔마켓 탭 전환 | 31.6ms | 10.6ms | 66.5% 감소 |
| 상품 선택 | 2.8ms | 2.0ms | 28.6% 감소 |
| 선택 한 번의 DOM 변경 | 246~248회 | 0~15회 | 같은 상품 선택은 0회 |
| 스크롤 호출+레이아웃 | 0ms | 0ms | 타이머 해상도 이하, FPS 개선 판단 불가 |

실행별 p95 중앙값은 재렌더 37.7→39.7ms, 탭 전환 52.3→19.4ms, 상품 선택 4.9→4.2ms다. 결과 원본 6개는 [비교 자료](../product/classroom-stationery-2026-10-07/index.html)와 같은 디렉터리에 보존했다.

1440px에서 퀘스트 행 높이 294→142px, 마켓 첫 상품 시작 위치 467→298px, 상품 높이 357→270px였다. 390px에서는 마켓 시작 위치 530→358px, 퀘스트 행 278→196px였다. 기존보다 콘텐츠를 먼저 볼 수 있다.

이 수치는 워밍업한 로컬 JS/레이아웃 측정이다. Firebase 초기 응답, 실제 통신, 최초 페이지 로딩 시간, 저사양 실기기 FPS 개선을 의미하지 않는다. 네트워크 전송량 대신 파일 자체의 용량을 비교했다. 전체 재렌더의 소폭 증가와 운영 네트워크 체감은 남은 확인 사항이다. 읽기처럼 보이는 economy board 호출도 일부 상태 저장 경로가 있으므로 실계정 호출로 측정하지 않았다.

## 검증

- `npm run check`: 전체 통과. 정적 검사, 단위/도메인·애플리케이션 검사, Firebase Emulator 규칙/동작, 브라우저 smoke, 교실 portrait/UI/loading 포함.
- 마지막 타이포·모바일 보완 후 `npm run check:static` 및 교실 UI smoke 재통과. 앱 번들은 소스로부터 정상 재생성했다. React 하위 앱 소스는 변경하지 않아 해당 빌드는 수행하지 않았다.
- 데스크톱 1440, 태블릿 768, 모바일 390/320px, 학생·교사 총 76 화면 조합의 가로 넘침과 탭 이동을 확인했다. 동일한 합성 데이터로 1440/768/390px 전후 스크린샷을 남겼다.
- 안전한 mock으로 완료 체크·제출·교사 승인·상품 선택/구매 위임·환전 계산/잔액 검사·사진/아바타 선택·재시도·오래된 계정 응답 차단을 검증했다. 재렌더 후 클릭 한 번이 중복 호출되지 않음도 확인했다.
- 키보드 탭, Enter로 상품 열기, Escape로 닫기와 원래 버튼 포커스 복귀, 필터·빈 결과, 누락 가격/0 구분, 깨진 이미지 대체를 확인했다.
- 모든 UI 하네스 요청은 로컬 public 파일 응답 또는 차단으로 처리한다. 실제 구매·지급·승인·학생 업로드는 하지 않았다. 운영 계정/모바일 실기기 E2E는 미실행이다.
