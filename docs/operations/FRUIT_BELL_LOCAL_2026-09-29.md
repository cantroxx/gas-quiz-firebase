# 딩동! 과일종 — 로컬 구현과 운영 연결 경계

날짜: 2026-09-29

> 후속 사용자 승인으로 온라인 대전과 실제 학생 랭킹 저장을 구현·배포했다. 현재 운영 상태는 [FRUIT_BELL_ONLINE_2026-09-29.md](FRUIT_BELL_ONLINE_2026-09-29.md)를 따른다. 아래 내용은 최초 로컬 단계의 기록이다.

## 구현 상태

할리갈리에서 착안한 독립 카드 반응 게임을 `public/fruit-bell/`에 만들었다. 직접 그린 SVG 과일과 종을 사용하며, 기존 보드게임의 상품 이미지나 로고를 사용하지 않는다. 정식 원작 규칙 전체를 복제한 버전이 아니라 **90초 카드 대결**이다.

- 네 종류 과일, 56장 덱, 모든 사람의 맨 위 카드 중 같은 과일 합이 정확히 5개일 때 종 치기.
- 내 차례 카드 뒤집기(F키/버튼), 3초가 지나면 자동 진행.
- 종은 pointerdown/keydown에서 즉시 눌림과 합성 소리로 응답한다. 서버 결과를 기다렸다가 조작 반응을 내지 않는다.
- 서버가 500ms 뒤집기 구간을 관리한다. 공개 전 카드/남은 덱은 클라이언트로 전송하지 않는다.
- 성공하면 테이블의 모든 쌓인 카드를 가져온다. 카드가 승자의 덱으로 날아가는 연출, 오종 흔들림, 동시 입력 안내가 있다.
- 오종은 남은 덱에서 다른 플레이어에게 한 장씩 지급한다. 덱이 부족하면 있는 만큼만 지급한다.
- 첫 유효 종 이후 서버 도착 간격 60ms 안의 추가 유효 종은 접전으로 처리한다. 카드는 유지하고 모두 다음 카드 공개까지 재입력을 막는다.
- 90초 뒤 남은 덱+자기 앞 카드 수로 우승을 정한다. 같은 카드 수면 공동 우승. 덱이 모두 소진되고 가져갈 수 없는 상태면 일찍 종료한다.
- 봇 3명과 연습, 2~4인 방 코드 대전, 모두 준비 후 방장 시작, 재접속, 12초 단절 시 취소.
- 390px 모바일/데스크톱 화면, 소리 끄기, 동작 줄이기, 키보드/터치 지원.

## 실행

```sh
npm run serve:fruit-bell
```

미리보기: `http://127.0.0.1:5327/fruit-bell/`

친구 대전은 서로 다른 브라우저 프로필/시크릿 창에서 같은 주소로 접속해 시험할 수 있다. 동일 브라우저 프로필의 탭은 같은 세션으로 복귀한다. 방에 재접속하면 새 플레이어로 추가하지 않는다.

같은 와이파이의 여러 기기로 시험하려면 사용자가 아래처럼 명시적으로 LAN에 바인딩할 수 있다. 클라이언트는 호스트 PC의 LAN IP를 사용한다. 이번 작업에서는 루프백 서버만 실행했다.

```sh
FRUIT_BELL_HOST=0.0.0.0 npm run serve:fruit-bell
```

서버는 `functions/fruit-bell/local-server.js`에 있지만 Firebase Functions export에는 연결하지 않았다. 기본 바인딩은 127.0.0.1, 추가 npm 의존성 없이 Node HTTP+SSE 지속 연결과 POST 입력을 사용한다. 운영 Firebase/Auth/Firestore에 연결하지 않는다. 별명은 이 서버 메모리에만 남는다. 서버 종료 시 방과 시험 랭킹이 초기화된다.

## 퀴즈타운 연결

- `public/js/school-rooms.js`: 게임 아지트 카드 추가.
- `public/battle/index.html`: 독립 아지트 카드 추가.
- `public/js/hideout-ranking-plaza.js`: 과일종 탭 추가. 로컬에서는 같은 서버의 시험 랭킹을 읽고, 운영 호스트에서는 준비 중 안내만 표시한다.
- `/?fruitBellRanking=1`: 로그인된 퀴즈타운에서 해당 랭킹 탭으로 연결하는 경로.
- `getRankingModeOptionsForQuiz`, `getSupportedRankingModeForQuiz`, `getRankingTargetForQuiz`와 `rankingRecords`, `userRankingSummary`, `quizKingSummary`를 조사했다. 과목 퀴즈 기록에 게임 점수를 섞지 않고 기존 아지트 게임별 탭 구조를 따랐다. 이 함수들과 컬렉션의 쓰기 경로는 변경하지 않았다.

시험 랭킹은 완료된 사람끼리의 경기만 집계한다. 단독 우승 3점, 공동 우승 1점, 나머지 0점. 같은 누적 점수는 공동 순위. 경기 ID로 중복 반영을 막고 연습/취소는 제외한다. 반응시간은 참고 기록일 뿐 랭킹 정렬 기준이 아니다. 세션 ID는 학생 ID가 아니며 시험 랭킹을 학생 프로필에 연결하지 않는다.

## 판정의 실제 한계

이 버전은 로컬 플레이테스트용 **서버 도착 기준** 판정이다. 클라이언트가 보내는 점수, 결과, 반응시간을 신뢰하지 않는다. 공개 전 과일 데이터도 보내지 않는다. 대신 카드 공개 패킷이 실제로 화면에 도착하는 시점과 입력이 서버에 도착하는 시점의 통신 차이가 남는다. 60ms 접전 기준은 잠정값이며 네트워크 차이를 완전히 보정하지 않는다.

브라우저 시계는 짧은 왕복 시간 표본으로 맞추지만 이 값은 화면 카운트다운에만 사용한다. 왕복 1ms 등의 로컬 측정치를 학생 기기/교실 와이파이 품질이나 공정성 보장으로 일반화하지 않는다. 서버 전송 시각부터 계산한 반응시간에는 통신과 표시 지연도 포함된다. 서버 재시작/여러 인스턴스 사이의 복구와 공유 상태는 아직 지원하지 않는다.

## 운영 반영 전 승인 대상

현재 로컬 구현을 운영 온라인 게임/공식 랭킹 완료로 간주하면 안 된다. 요청 없는 deploy, commit, push는 실행하지 않았다. `firestore.rules`, `firestore.indexes.json`, `functions/index.js` 및 기존 학생 데이터는 이번 작업에서 수정하지 않았다. 작업 시작부터 이 파일들을 포함한 다수의 미커밋 변경이 있었으며 보존했다.

공식 연동을 위한 다음 범위는 사용자 승인 후 구현/배포한다.

1. 지속 연결 게임 서버 호스팅과 운영 URL/rewrite, 재시작 및 다중 인스턴스 정책 확정.
2. 기존 Firebase 로그인 토큰 검증, `authLinks`의 회원 연결 및 활성 사용자 확인. 별명/학생 ID를 클라이언트 입력만으로 신뢰하지 않기.
3. 별도 `fruitBellMatches` 완료 기록과 `fruitBellRanking/fruit-bell-90-v1/entries` 집계를 서버 전용으로 저장. 경기 ID 기준 원자적 중복 방지, 중도 이탈/봇 제외, 실제 참가 확인. 기존 퀴즈 랭킹·DJ코인 컬렉션은 쓰지 않기.
4. 랭킹 읽기 접근, 비공개/비활성 회원 제외, 기존 프로필 표시 정책 적용. Rules 변경이 필요한 경우 정확한 규칙 diff와 에뮬레이터 허용/거부 검증 후 별도 확인.
5. 교실 실제 기기에서 공개 시점 차이, 입력 왕복 분포, 터치/키보드 차이를 측정하고 접전 기준/지연 큰 경기의 공식 기록 제외 정책 확정.

이는 아직 연결하지 않은 운영 설계이며 현재 읽거나 쓰는 Firestore 경로가 아니다.
