# 교실 증권 C·D단계 — 2026-10-18

사용자 승인: “c,d단계 진행하고 보고”. 시범 학급은 후속 답변 “4-8”로 지정했다. 실제 교실 문서 ID는 `G4-C8`다. 이전 A·B의 연습 시장을 DJ코인 시장으로 전환하지 않고 `coin-v1`을 별도로 사용한다.

## 구현

- `userEconomy/{memberUserId}`와 증권 계좌·입출금 원장·요청 결과·일별 한도·학급 준비금을 한 Firestore transaction에서 갱신한다.
- 기존 지갑의 `djCoin ?? coin ?? 0` 우선순위를 유지한다. 명시적인 `djCoin: 0`을 다른 필드로 대체하지 않는다. 입출금 성공 시 두 별칭을 동일한 정수 잔액으로 기록하고, 다른 지갑 필드·포인트·퀴즈 보상·XP는 변경하지 않는다.
- 실제 계좌 초기 지급은 0이다. 학생이 계좌 시작과 입금을 직접 선택한다. 정수 코인만 입출금하고 소수 예수금은 남긴다. 연습 시장 입출금과 mode 변경은 거부한다.
- 동일 UUID와 payload는 커밋 후 응답 유실·새로고침·다음 날짜·거래 중지 상태에서도 기존 결과를 돌려준다. 회원·학급 권한은 재검증한다.
- 하루 총입금 100코인, 누적 순입금 300코인, 입금·매수 후 순자산 500코인, 학급 누적 순유출 1,000코인 기준을 적용한다. 출금으로 하루 입금 한도가 복원되지 않는다.
- 순유출 기준 도달 시 신규 입금·매수를 계속 차단한다. 교사가 단순히 거래 재개를 눌러 이 제한을 해제할 수 없다. 거래 중지·기능 끄기 중에도 조회·정상 예수금 출금·개장 시간의 보유 주식 매도를 유지한다. 동결 계좌의 새 쓰기는 거부한다.
- 교사 화면에 총입금·총출금·실현손익·수수료·순유출과 일별 보고를 표시한다. 마감 후 평가액·평가손익 snapshot을 별도 기록하며, 원장 검산은 입출금 보존식도 확인한다. 자동 잔액 보정은 없다.
- 학생 화면에 지갑 잔액·한도·정수 출금 가능액·두 번의 확인 단계를 추가했다. 응답 유실 후 이전 요청 재확인을 유지하고 지갑·교실 캐시를 무효화한다.

## 운영 도입 범위

- 신규 callable 3개: `classroomSecuritiesQuery`, `classroomSecuritiesAction`, `classroomSecuritiesAdminAction`.
- 신규 scheduled function 1개: `classroomSecuritiesTick`. Asia/Seoul 매분 확인, 재시도 3회, 최대 인스턴스 1. 명시된 `G4-C8/coin-v1`만 처리한다. 예약 뉴스, 일별 시세, 마감 평가를 담당한다.
- 첫 거래일: 2026-10-19, 평일 09:30~14:30. 아직 첫 시세가 없을 때 목록을 참고 시작가로 안내하고 주문은 막는다.
- **교사 시범으로 시작한다.** `studentAccess:false` 상태에서는 학생 요청을 서버에서도 거부한다. 교사는 수업 1회 이상 점검 결과를 10자 이상 기록한 뒤 “수업 점검 완료 · 학생 공개”로 해당 학급을 열 수 있다. 학생 공개 뒤 계좌 접근 자체를 끄는 동작은 제공하지 않는다.
- 초기화는 시장·가상 기업·비공개 엔진·0원 준비금·배포 감사 기록만 생성한다. 실제 학생 계좌·원장·지갑에 테스트 거래나 일괄 지급을 만들지 않는다.
- Firestore 규칙은 신규 하위 경로를 기존 기본 거부 규칙으로 차단한다. 실제 운영 규칙 사본을 Emulator에서 검사했다. 증권 때문에 규칙·인덱스·Storage 설정을 배포할 필요는 없다.
- 다른 퀴즈·교실 작업을 보존하기 위해 현재 운영 Hosting manifest를 복제하고 파일 12개만 반영한다. 공유 bundle의 교실 모듈 4개에는 증권 연결 부분만 삽입한다. 전체 로컬 app shell을 덮어쓰지 않는다.
- Functions는 기존 운영 source에 신규 증권 모듈을 추가하고 네 함수만 배포한다. 기존 인증·회원·교사·학급 검사 함수의 본문이 로컬과 동일함을 확인했다.

## 공급량 검토

4-8의 읽기 전용 집계에서는 활성 학생 22명, DJ코인 총량 5,976, 중앙값 230이었다. 원본 학생 식별정보와 지갑 문서는 보고서에 저장하지 않았다.

다음은 예측이 아닌 스트레스 계산이다. 합성 학생 22명이 각 1,000코인을 가진다고 가정하고, 첫 3일에 100코인씩 입금한 뒤 한 기업을 자산의 50% 이내로 매수하고 기간 말에 전량 매도·정수 출금한다. 실제 학급 모두가 300코인을 입금할 수 있다는 뜻은 아니다. 이후 추가 매수는 없다.

단위는 학급 전체 DJ코인 지갑의 순증감이다. 수수료와 소수 예수금 잔류를 포함했다. 가격은 실제 엔진과 같은 1~1,000코인 범위를 적용했다. 균일 상승은 실제 HMAC 가격 엔진의 발생 확률을 뜻하지 않는다.

**1,000코인 기준은 공급량 상한을 보장하지 않는다.** 기존 보유분 매도·출금을 보장하므로 평가이익을 실현할 때 기준보다 큰 공급이 발생할 수 있다. 이 결과를 사용자에게 먼저 알리고 교사 시범→수업 점검→학생 공개 순서로 도입한다. 더 엄격한 공급량 상한·가격 정책·시즌 종료 정책은 별도 설계 대상이다.

## 재현·운영

```sh
npm run test:securities
npm run check:securities-emulator
SECURITIES_PRODUCTION_TEST=1 npm run check:securities-callable
node scripts/audit/securities-supply-simulation.js

```

설치된 Java 26의 `sun.misc.Unsafe` 경고를 Storage Emulator가 오류로 처리하는 경우, 환경변수 `JAVA_TOOL_OPTIONS`도 안내 문구를 출력하므로 도움이 되지 않는다. 이번 검증에서는 `/tmp/securities-java-bin/java`가 `/usr/bin/java --sun-misc-unsafe-memory-access=allow "$@"`를 실행하도록 하고 PATH 앞에 두었다. 저장소·시스템 Java 설치는 변경하지 않았다.

중단은 교사 화면의 거래 중지를 사용한다. 조회·정상 청산·출금을 유지하고 UI만 이전 버전으로 돌려 계좌 접근을 없애지 않는다. 시세 누락은 교사 화면의 누락 거래일과 Cloud Functions 오류 로그를 확인한다. 과거 가격·원장 수정, 학생 계좌 초기화, 강제 청산은 이 작업에서 제공하지 않는다.

배포 준비·검증·초기화 스크립트는 `scripts/maintenance/*securities*.js`, 읽기 전용 운영 검사와 공급량 계산은 `scripts/audit/*securities*.js`에 있다. 스테이징 소스·로그·원격 manifest는 `/tmp/securities-cd-20261018/`에 보관한다. 커밋·푸시는 하지 않는다.
