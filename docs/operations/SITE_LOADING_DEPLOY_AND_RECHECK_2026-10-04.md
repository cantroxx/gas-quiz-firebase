새 교실 디자인 배포가 끝난 버전을 기준으로 다시 측정했다. 조건별 중앙값이며 새 브라우저 컨텍스트의 첫 방문과 같은 컨텍스트의 즉시 재방문을 구분한다. 인증·Firestore·Functions·Storage API는 차단했다. 학생 로그인 완료 시간은 아니다.

| 속도 제한 없는 첫 방문 | 1,064→1,204ms | 1,268→1,392ms | 1.302→1.304MB |

## 추가 병목과 다음 순서

### 1. 코디 상품 목록의 큰 전송량

로그인 없이 공개 JSON 4개만 실제 운영에서 읽는 별도 검사에서도 병목을 확인했다. 4Mbps·80ms·CPU 4배 감속 조건의 3회 결과는 3,663 / 3,714 / 3,708ms였다. 중앙값 **3.71초**, 실제 Brotli 전송량 중앙값 **약 1.716MB**이며, 그중 `verified-top50.json` 하나가 약 **1.622MB**다. 전체 상점 사용 가능 시간은 아니며 카탈로그 다운로드·문자열 해석·JSON 파싱까지의 시간이다.

해당 파일 원본은 4,721,086바이트이고 2,689개 표시 행에 긴 검증 해시 약 275만 글자가 포함된다. 현재 화면은 최상위 `itemsByCategoryGender`를 소비하며 항목의 검증용 `hash`·`imageBytes`는 사용 경로를 찾지 못했다. 코디의 인물 미리보기 `look.hash`는 별도 기능이므로 구분해야 한다.

원본은 그대로 두고, 메모리에서 화면용 필드만 남겨 본 분석 결과:

| 데이터 | 원본 바이트 | gzip 비교 바이트 |
| --- | ---: | ---: |
| 현재 전체 JSON | 4,721,086 | 1,972,963 |
| 화면용 데이터 후보 | 775,071 | 75,135 |

이는 **미적용 용량 실험**이다. gzip 약 96.2% 감소 가능성이 있으며, 실제 Hosting의 Brotli 전송량 감소나 상점 속도 96% 향상을 뜻하지 않는다. 원본 검토 데이터를 보존하고 별도 화면용 카탈로그를 생성하는 방향이 적절하다. 상품 코드·가격·자격 필터·이미지·성별·추천 순서 일치 검증이 필요하다.

현재 fetch와 Hosting JSON 응답 모두 `no-store`이므로 상점 문서를 새로 로드하면 다시 받는다. 다만 기존 앱 상점은 이미 열린 iframe을 재사용하므로 단순 탭 왕복마다 모두 재다운로드한다고 볼 수 없다. 버전이 붙은 공개 카탈로그의 캐시 정책은 사용자 잔액 응답과 구분해 검토해야 한다.

### 2. 교실 전체 조회 범위와 순차 대기

로컬 `functions/index.js:6282`의 경제 게시판 함수는 권한 확인 후 직업·상품·숨김 상품·직업 배정·루틴·루틴 기록·지원 목록을 차례로 기다린다. 이후에도 여러 조회 묶음이 이어진다. 필요한 조회의 병렬화와 홈/탭별 데이터 분리가 전체 조작 가능 시점의 후속 후보다. 이번 배포는 서버 함수를 변경하지 않았다. 운영 서버 실행 설정·콜드 스타트·실제 소스 일치 여부까지 확인한 것은 아니다.

학생 목록은 callable 후 학생별 `userLevelSummary`를 읽는다. 합성 학생 22명에서 callable 공급자 1회 + 레벨 문서 공급자 22회를 다시 확인했다. 실제 HTTP 요청 수나 과금 읽기 수와 동일하다는 뜻은 아니다.

경제 조회 함수는 미션 달성일을 조건부로 저장하는 경로도 있다. 따라서 이번 점검에서는 운영 학생 계정으로 해당 함수를 호출하지 않았다. 실제 교실 서버 지연은 별도 측정 범위다.

### 3. 첫 접속 자산과 재진입 초기화

배경과 글꼴이 초기 전송량 대부분을 차지한다. 작은 화면용 배경과 필요한 글꼴만 먼저 읽는 방식을 비교할 가치가 크다. 메인 앱 내부 화면 전환은 이미 DOM을 숨기고 보여주는 구조지만, 하우징 등 독립 문서 이동은 문서를 다시 로드한다. 캐시된 자산과 앱·인증 상태 재초기화 비용은 별도로 보아야 한다.

인증 콜백과 익명 로그인 완료가 겹치는 합성 시나리오에서는 회원 복원 공급자 및 목적 화면 진입이 각각 2회 호출됐다. 관련 운영 공개 모듈과 로컬 파일 일치를 확인했다. 실제 중복 HTTP 요청을 측정한 결과는 아니며, 인증 복원 요청 공유와 한 번만 화면 전환하는 처리가 후속 후보다.
