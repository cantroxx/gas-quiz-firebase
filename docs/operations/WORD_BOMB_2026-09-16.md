## 사용자와 확정한 게임 방향

- 2~8인이 순서대로 끝말잇기를 하고 폭탄을 넘긴다.
- 차례마다 머리 위의 폭탄 카운트가 방장이 고른 **5·10·15·20초**로 초기화된다.
- 일반 대전: 총 경기 시간 제한 없음, 시작 하트 1·2·3개(기본 2), 폭발 −1, 마지막 생존자 승리. 탈락자는 관전한다.
- 타임 챌린지: 총 1·3·5분(기본 3분), 개인 타이머와 전체 타이머를 분리한다. 성공 +10점, 폭발 −10점, 탈락 없음. 최고 점수 승리, 동점 공동 우승.
- 전체 경기 종료 시 진행 중 차례에 폭발 감점을 부여하지 않는다.
- 모두 같은 서버 시각에 차례를 시작한다. 전달 구간 1초 뒤 개인 제한 시간이 시작되고, 챌린지의 전체 시간은 계속 흐른다.
- 봇 1~7명과 연습 가능. 힌트는 연습에서만 제공한다.
- 일반 대전 및 챌린지 모두 중도 나가기는 항복. 연결만 끊긴 경우 시간은 계속 흐르며 같은 계정으로 재입장 가능.

## 사전과 판정 범위

국립국어원 기초 어휘 XLSX(공공누리 제1유형)의 명사와 기존 교실 낱말로 정확히 10,000개를 구성했다. 전체 국어사전은 아니며 모든 항목을 교사가 개별 검수하지는 않았다. 출처·선정 과정은 `public/word-bomb/DICTIONARY_NOTICE.md`, 낱말별 출처는 `fixtures/word-bomb/dictionary-v2-provenance.json` 참조. 기존 12글자 제한을 폐지하고 비정상 입력 방지 상한 100글자를 적용했다. 목록 밖 단어도 온라인 제안 투표로 인정할 수 있다.

두 글자 이상의 한글 낱말, NFC 정규화, 첫 글자 연결, 두음법칙, 경기 전체 중복 금지, 남은 사전 기준 한방 단어 제한을 적용한다. 다음에 쓸 수 있는 연결이 모두 막히면 낱말 사용 기록을 보존한 채 새 시작 낱말을 고른다. 사전을 소진하면 현재 성적으로 종료한다.

실시간 사전 검색은 대전 중 닫는다. 클라이언트에도 목록이 있어 개발자 도구를 통한 열람까지 차단하지는 않는다. 공식 랭킹·DJ코인과 연동하지 않은 친선 대전이다.

## 온라인 구조와 운영 데이터 경계

### 제안 투표와 새 캐릭터

- 사전 밖 단어와 한방 단어를 온라인에서 제안할 수 있다. 연결 글자·중복·금지 표현 검사는 투표로 우회할 수 없다.
- 제안자를 제외한 생존 학생의 과반수: 2인전 1/1, 3인전 2/2, 4인전 2/3 동의. 제안자와 봇은 투표하지 않는다.
- 차례당 제안 한 번, 최대 20초. 투표 동안 폭탄 및 챌린지 전체 시계를 멈춘다. 반대·미달·시간 초과에는 남은 차례 시간으로 돌아간다.
- 서버 트랜잭션으로 표를 집계한다. 재전송 표는 한 번만 세며 이탈로 통과 기준을 낮추지 않는다. 승인 단어는 해당 경기 한정이며 공용 사전에 저장하지 않는다.
- 캐릭터는 builtin 이미지 생성으로 제작한 곰·토끼·고양이·수달 4종. `public/word-bomb/assets/characters-v2.png`를 CSS 스프라이트로 사용한다. 전달·폭발·차례 애니메이션 유지, 모바일 배치 조정.
- 생성 프롬프트: `docs/product/WORD_BOMB_CHARACTER_PROMPT_2026-09-16.json`.
- 후속 검증 완료: 14개 도메인 검사, 정적 검사, 실제 Chrome 모바일·봇 게임 검사 통과. 독립 Firebase 에뮬레이터에서 4인 동시·중복 투표 및 만료 저장, 실제 2계정 브라우저에서 긴 단어 제안·타이머 정지·새로고침 복귀·동의·반대·차례당 제안 제한 검증 통과. 전체 저장소 검증의 기존 공용 포트 제한은 아래 기록과 같다.

### 데이터 접근

- 새 컬렉션: `wordBombRooms/{6자리번호}`, `wordBombPlayers/{authUid}`.
- 기존 `authLinks` 및 `users`는 회원 활성 여부·닉네임 확인에만 읽는다.
- 학생 계정, 기존 랭킹, DJ코인, 하우징, 기존 낱말대전 기록에 쓰지 않는다.
- 새로운 보안 규칙 권한을 열지 않았다. 현재 catch-all deny가 새 컬렉션의 클라이언트 직접 읽기·쓰기를 막는다.
- 인증된 callable가 매 요청에서 활성 회원·방 참가자 여부를 확인하고, Firestore 트랜잭션으로 방을 갱신한다. 점수·차례·마감은 서버가 판정한다.
- 실시간 관찰은 callable `watch`가 Admin SDK snapshot을 최대 20초 기다리는 long polling 방식이다. 상태 변화 또는 마감 시 반환하고 다시 구독한다. `revision`으로 뒤늦게 도착한 화면 상태를 무시한다.
- 호스트가 끊겨도 다른 참가자의 관찰 요청이 시간 초과를 진행시킨다. 전원 접속이 끊기면 다음 접근 시 서버 마감 시각을 기준으로 누적 초과를 계산한다.
- 장시간 관찰 요청 수는 연결된 학생 수와 비례한다. 향후 동시 이용 규모 확대 시 Functions 비용·동시성 지표를 확인할 것. 현재 운영 부하 검증이나 비용 측정은 하지 않았다.
- 방 생성은 충돌 검사, 계정별 활성 방 제한, 최대 4인 트랜잭션 정원을 적용한다. 대기실은 40분 뒤 만료되며 나간 방장의 역할은 다음 참가자에게 넘어간다.
- 자동 데이터 삭제·TTL·랭킹 집계는 도입하지 않았다. 종료 방 보관/정리 정책은 별도 결정한다.

## 낱말대전 교체 순서

사용자 의도: 새 게임이 만들어진 뒤 기존 낱말대전을 정리한다.

1. 새 게임 로컬 구현 및 에뮬레이터 대전 검증: 완료.
2. 미커밋 작업의 배포 범위를 구분하고 전체 `npm run check` 통과 뒤 사용자 요청에 따라 Hosting + `wordBombAction` 배포: 완료.
3. 운영 공개 화면·봇·인증 검사 완료. 아지트 낱말대전 카드를 말폭탄 카드로 교체. 기존 게임 파일 및 서버 기능은 유지.
4. 기존 랭킹/방/학생 기록은 자동 삭제하지 않는다. 보존·공개 범위 변경과 파일 삭제는 구체적 대상을 정리하고 별도 확인.

현재 낱말대전의 파일·데이터 및 직접 URL은 유지하며 아지트 메뉴는 말폭탄으로 전환했다. 파일·기록 삭제나 랭킹 정리는 수행하지 않았다.
