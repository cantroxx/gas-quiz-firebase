# 교실 후작업 실행 계획·결과

기준: [기존 후작업 F-01~F-16](CLASSROOM_BOARD_FOLLOWUPS_2026-10-21.md). 작성 2026-10-21.

> 추가 지시에 따른 최종 총점검 결과는 [검증 문서 마지막 절](CLASSROOM_POST_FOLLOWUP_VERIFICATION_2026-10-21.md#최종-총점검-결과--2026-10-21)을 따른다. 코드 검사는 통과했으며 실제 이전은 원본·미처리 계약·실행 및 복구 준비 미완료로 보류다. 아래 ‘총점검 미실행’ 표현은 후작업 종료 시점의 이력이다.

## 실행 경계

후작업 구현 → 후작업 이후 검증 → 최종 총점검 직전 정지. 배포, 운영 데이터 변경, 실제 이전, commit/push는 실행하지 않는다. 하트베리는 DJ코인, 포인트는 교실 포인트로 보존한다. 실제 이전은 모든 후작업과 별도 총점검 이후에만 진행한다.

## 사용자 확정 사항

- 농장: DJ코인 씨앗 구입·심기·수확, DJ코인 소비처 추가.
- 배경: 농장 스킨. 교실 상점에 DJ코인 상품 지원.
- 복권: 구입·추첨·지급·과거 기록을 갖춘 기능.
- 외부 주식: 회사 동일성을 강제하지 않고 원본 수치 중심 기록 보존.
- 전자칠판: 1920×1080, 브라우저 배율 100%를 기본 검증 환경으로 사용.

### 새 화면 사용 흐름

교실 → **농장·교실 생활과 경제**. 학생은 자신의 농장·소유물·루틴·직업·예금·환전·신청·복권·내역을 확인한다. 교사는 대상 학생을 선택하고 **교사 설정·관찰**에서 정책과 상품을 등록한다. 교사 화면은 개인 조작용이며 학생 잔액·관찰을 전자칠판에 공개할 용도로 쓰지 않는다. 전자칠판 수업 보드는 계속 기본 공개 모드로 열린다.

- 원본 기록, 거래, 루틴, 예금, 신청, 복권 내역은 **내역·원본 기록 → 전체 기록 찾아보기**에서 100건씩 추가 조회한다.
- 화면의 한도에 도달하면 안내한다. 보이는 일부 행의 합계를 전체 잔액 대조 근거로 사용하지 않는다.
- 통신 응답이 유실되면 동일 요청 번호로 결과를 다시 확인한다. 서버는 요청 내용이 다르면 같은 번호 재사용을 거부한다.
- 교사 설정은 실 운영에 자동으로 채워 넣지 않았다. 예시 씨앗 가격·이자·급여는 합성 검사값이며 확정된 운영 정책이 아니다.

### 복권 원본 재확인

2026-10-21 [그라운드 텃밭 은행](https://growndcard.com/cards)의 학생용 기금 복권과 관리자 복권 탭을 조회했다. 세 칸은 각각 한 자리 숫자이며 합쳐서 1~100의 번호 하나를 입력한다. 원본은 교사 추첨, 미당첨 가능, 같은 번호 당첨자 상금 분할을 안내한다. 구매·추첨·저장 버튼은 실행하지 않았다. 이전에 만든 단일 당첨 티켓 추첨 방식은 이 확인 후 번호 추첨 방식으로 교체했다.

## 실제 이전에 사용할 입력 계약

합성 예제: `fixtures/classroom-board/grownd-followups-example.json`, `target-followups-example.json`.

```sh
node scripts/migration/preview-grownd-followups.js SOURCE.json TARGET_SNAPSHOT.json
```

이 명령은 Firebase를 초기화하지 않는다. 출력에는 원본 본문이 들어갈 수 있으므로 실제 자료의 출력은 `private/` 또는 `exports/`와 같은 비공개 경로에 보존하고 공개 Git 문서에 복사하지 않는다.

- 기존 학생/활동/젬 매핑과 잔액에 더해 `snapshotAt`, 분류별 `scope`, `funds`, 대상 `wallets` 스냅샷 필요.
- 11개 분류: `routines`, `jobs`, `deposits`, `exchanges`, `inventory`, `growth`, `requests`, `observations`, `diaries`, `securities`, `lottery`. 원본에 없는 분류도 빈 배열과 확인 건수 0을 명시한다.
- 기존 `records`의 활동 본문도 `questHistory` 원본 보관안에 포함한다. 상태/지급 여부만 남기고 원문을 버리지 않는다. 열람 범위 `owner`/`teacher`를 명시한다.
- `files`에는 학생 대응, 상대 경로, 원본 바이트 수, MIME, SHA256, 열람 범위를 기록한다. 실제 파일은 JSON 폴더 내부여야 하며 외부 경로·외부 심볼릭 링크·중복 ID·형식/해시 불일치를 거부한다. 검증 도구의 파일당 한도는 25MB다.
- 품목 대응 `maps.items`는 `seed`/`skin`/`coupon`/`archive`와 대상 상품 코드를 사용한다. 원본 효과 설명은 그대로 보존하며 미정 효과를 새 보너스로 임의 지급하지 않는다.
- 열려 있는 예금, 미추첨/미지급 복권, 미지급 급여·루틴 보상, 검토 대기/승인 후 미지급 신청은 원본 정산 또는 개별 승계 계획 확정 전 준비 완료를 차단한다.
- 전후 지갑은 기준 시각 이후의 명시적 교체 계획이다. 현재 잔액에 원본 잔액을 단순 가산하지 않는다. 하트베리→DJ코인, 포인트→교실 포인트 대응은 변경하지 않는다.

### 원본 이미지 보관 설계

원본은 미리보기로 대체하지 않는다. 실제 파일이 확인되면 비공개 원본 경로 `classrooms/{classId}/migrationOriginals/{batchHash}/{sourceId}/{sha256}`와 학생/교사 열람 메타데이터를 함께 계획한다. 공개 링크를 만들지 않고, 기존 원본은 총점검·이전 대조 완료까지 삭제하지 않는다. Storage 업로드 경로와 서버 열람 구현은 실제 파일 필요 여부·보존 기간을 확정하는 총점검의 실행 범위에 포함한다. 이번에 원본 Storage 업로드 기능을 배포하거나 무손실 원본 열람까지 운영 완료했다고 판정하지 않는다.
