# 생성형 과목 퀴즈 구현 및 전환 메모

상태: **2026-10-17 운영 배포·검증 완료.** 생성형 과목 퀴즈 및 과목별 누적 랭킹을 활성화했다. 새 랭킹은 전원 0점에서 시작하며 기존 과목 랭킹 원본은 보존했다. 상세 배포 기록은 `SUBJECT_QUIZ_BATCH_DEPLOY_2026-10-17.md`와 같은 이름의 JSON에 있다.

## 구현 범위

- `functions/subject-quiz/`: 49개 단원/주제, 생성기, 서버 채점, 진행·통계·과목 통합 누적 랭킹.
- `public/subject-quiz/`: 학기/역사/단원 선택, 연습전/랭킹전, 짧은 해설, 하트·타이머, 도형·그래프, 과목 랭킹.
- `public/js/data/subject-quiz-catalog.js`: 서버 교육과정 정본에서 생성한 메뉴. 기존 공유 카탈로그의 메타데이터를 보존하고 과목 메뉴만 새 엔진으로 교체한다.
- 기존 퀴즈 시작 링크는 생성형 과목 화면으로 연결한다. 원코/노힌트/스피드는 새 과목 엔진에 없다.
- 기존 랭킹 광장의 과목 보드는 단원/모드 탭 없이 누적 점수를 표시한다. 종합 퀴즈왕은 인기 퀴즈 기여분과 새 과목 누적 점수를 합산한다. 개인 랭킹 조회에서도 이전 과목 기록을 제외한다.

## 데이터 경계

새 서버 전용 컬렉션:

- `subjectQuizRuns/{uuid}`: 소유자·시간·하트·현재 문항·서버 seed·최근 중복 방지 지문·마지막 제출 결과.
- `subjectQuizPlayers/{memberId}`: 현재 판과 시작 요청의 멱등성 키.
- `subjectQuizProgress/{version}_{memberId}`: 단원별 연습/랭킹 정답·풀이 수. 고정 100문제 완료율을 사용하지 않는다.
- `subjectQuizRankings/{version}/{subject}/{memberId}`: 과목 통합 누적 정답 수.

읽기·쓰기는 `subjectQuizAction` callable을 통한다. 기존 Firestore 최종 거부 규칙에 의해 브라우저에서 새 컬렉션을 직접 읽거나 점수를 쓸 수 없다. 클라이언트 응답에는 현재 보기만 포함되며, 정답·해설은 제출 후 제공한다.

`grantPracticeRewardInTransaction`은 기존 연습 보상 구현을 추출한 내부 함수다. 기존 callable은 예전 연습 기록 확인을 유지한다. 새 엔진만 서버가 확인한 정답으로 내부 함수를 호출한다. 기존 `rewardDailyCaps`의 50코인 한도·오늘의 퀴즈 XP 한도·레벨 계산을 공유한다. 새 정답도 `dailyUsage`의 교육 정답 수와 성장 퀘스트에 반영한다. 랭킹 정답에는 문제당 코인을 주지 않는다.

## 랭킹 초기화 방식

물리적으로 과거 기록을 일괄 삭제하지 않고 새 버전으로 점수를 분리한다. 초기 상태는 전원 0점이다.

1. 새 과목 랭킹은 새 버전 경로만 읽는다.
2. `rankingRecords` 중 구형 과목 ID/분류에 해당하는 행을 새 광장·개인 랭킹에서 제외한다.
3. `quizKingSummary.categories`에서 구형 과목 기여분을 제거한 뒤 새 누적 점수를 합산해 표시한다. 원본 요약 문서는 수정하지 않는다.
4. `userRankingSummary` 원본은 보존한다. 새 과목 점수의 저장·조회에 사용하지 않는다.
5. 전환 플래그 `appSettings/featureFlags.subjectQuizEnabled=true`와 전환 규칙을 함께 적용하면 구형 클라이언트의 과목 `rankingRecords` 생성이 거절된다. 인기 퀴즈 생성은 계속 허용한다.

2026-10-17 운영 읽기 전용 점검에서 119개 종합 요약 문서의 분류 필드 구조를 확인했다. 구형 `역사-인물` 별칭도 제외 목록에 포함했다. 분류가 단지 `인물`인 원본 행은 어느 분야인지 입증할 수 없어 임의로 과목 기록으로 판단하지 않는다.

새 버전 원본을 제외한 이전 기록은 보존되므로, 이전 Hosting 버전으로 되돌리고 전환 플래그를 해제하는 방식으로 롤백할 수 있다. 새 버전에서 얻은 코인·XP 등 이미 지급된 보상은 롤백 시 회수하지 않는다.

## 운영 반영 순서

현재 작업 공간에는 다른 작업의 변경이 많이 있다. 로컬 전체 Hosting/Functions/규칙을 그대로 배포하지 않는다.

1. 현행 배포본을 다시 조회하고 이 작업의 공유 파일 변경만 합친 배포 후보를 준비한다. 해당 작업의 생성기 폴더/standalone UI는 신규 파일로 포함한다.
2. Functions는 현행 `grantPracticeReward` 배포 소스를 기준으로 보상 내부 함수 추출·새 `subjectQuizAction`·필요 모듈을 반영하고 새 callable만 배포한다. 기존의 다른 callable을 함께 배포하지 않는다.
3. 운영 규칙 원문에 `canWriteCurrentQuizRanking`과 한 줄의 호출 조건만 반영한 후보를 검증한다. 로컬 규칙에는 다른 작업 변경이 있으므로 전체 복사하지 않는다.
4. Hosting 후보에서 과목 메뉴·공유 랭킹의 새 경로를 검증한 뒤 반영한다. 버전/전체 파일 해시를 비교해 작업 외 파일이 보존됐는지 확인한다.
5. `subjectQuizEnabled=true` 전환 플래그를 적용한다. 새 버전 점수 분리와 구형 점수 재등록 차단을 확인한다. 운영 학생 계정으로 임의의 답 제출·코인 지급 테스트를 하지 않는다.
6. 새 과목 4개 랭킹이 0점에서 시작하며 인기 퀴즈·기존 코인·뱃지에 영향이 없는지 읽기 전용 확인 후 배포 버전과 결과를 보고한다.
