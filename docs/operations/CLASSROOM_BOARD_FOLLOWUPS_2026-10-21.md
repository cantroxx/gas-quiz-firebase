## C. 실제 운영 반영 준비

1. 원본 내보내기 범위와 기준 시각, 계정 매핑을 확정한다. 닉네임·번호 단독 자동 매칭 금지.
2. 교사/추가 학생/누락 학생, 중복 젬·미정 가격을 확인한다. 운영 상품 값을 임의 추정하지 않는다.
3. 미지원 데이터의 보존 위치와 접근 권한을 확정한다. 학생 원본은 공개 Git 문서에 넣지 않는다.
4. 사전 검증 결과와 변경 전후 대상·금액·기록 수, 재실행·복구 계획을 사용자에게 제시한다.
5. 요청된 배포·실제 이전만 실행하고 결과를 대조한다. 보드 구현 승인을 운영 대량 지급 승인으로 간주하지 않는다.

### 전체 점검 판정

- `npm run check`: 통과. 기존 교실 회귀와 과목 퀴즈 2,502개 화면 검사까지 종료 코드 0.
- 새 보드: 도메인·실제 저장 핸들러·합성 Firestore 트랜잭션·Chrome 검증을 별도로 갖췄다. 마지막 작은 보완까지 전용 검사를 재통과했으며 목표 문서의 검증 표에 기록했다.
- 운영 배포·실데이터 이전·실제 전자칠판 현장 검증: 미실행.
- 단계 1~3의 구현 실패를 위 목록으로 넘겨 완료로 처리한 항목은 없다. 구버전의 근거 없는 회수를 거부하는 것은 2차의 명시적 안전 처리이며 F-11은 처리 가능한 구버전 범위를 넓히는 후속 작업이다.
- 그라운드 전체 기능 대체는 F-01~F-10의 차이를 해소하기 전까지 완료로 부르지 않는다.
