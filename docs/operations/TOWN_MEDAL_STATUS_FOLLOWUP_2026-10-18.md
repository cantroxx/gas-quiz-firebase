# 훈장·빈 상태창 후속 보고

## 훈장
1~100 훈장 내부 숫자를 모두 제거했다. 10개 등급의 금속/리본/보석 색상, 등급 내 보석 크기·세공·장식으로 상승을 표현한다. 레벨 매핑/실제 레벨 상한은 변경하지 않는다. SVG와 브라우저 디코딩 100개 검사 통과.

## 빈 상태창 원인
사용자 설명: 새 게시판 배경은 나오지만 정보가 없고 전체/오늘/이번 주 문구만 표시.
배포 전 HTML에는 quest-fold/quest-count가 없다. 해당 HTML이 캐시된 상태에서 새로운 status.js를 받으면 clear()가 없는 quest-count의 replaceChildren()을 호출해 중단된다. 이 조합으로 빈 프로필과 정적 기간 버튼만 남는 현상을 재현했다.
코인·레벨 문서가 삭제된 문제가 아니다. 이전에 보고된 관리자 계정의 코인/레벨 문서 존재와 단일 계정 연결을 읽기 전용으로 확인했다. 실제 사용자의 브라우저 캐시를 직접 읽은 것은 아니며, 증상과 일치하는 코드 조합을 재현했다.

## 수정
- 오래된 HTML 구조를 새 구조로 보완한 뒤 인증/렌더링 시작.
- 팝업 URL을 `/player-status/index.html?v=jewels-20261018&view=status`로 변경. HTML용 재검증 헤더가 적용되는 명시적 파일 경로 사용.
- 마을 팝업은 부모의 Firebase 연결과 인증 상태 재사용. 부모에서 연결된 회원 문서를 직접 읽고 authUid 일치 검증. 독립 페이지는 기존 검색 경로 유지.
- 프로필, 코인·레벨을 먼저 표시하고 퀘스트/보상은 별도로 로드. 12초 지연 제한과 오류 안내·재시도 제공. 닫을 때 인증 구독 정리.
- 상태 문서/호출 스크립트/훈장 URL의 캐시 버전 갱신.

## 검증
새 HTML과 구버전 HTML 각각 실제 후보 브라우저 검사 통과. 느린 응답/무응답, 수령 후 갱신, 부모 인증 재사용, 구독 해제, 계정 전환, 모바일, 장소 내 팝업 경로를 검사했다. 학생 실데이터 변경이나 재초기화는 수행하지 않았다.
에뮬레이터에서 회원 직접 조회/검색 모두 허용됨을 확인하여 조회 권한 문제와 구분했다.
