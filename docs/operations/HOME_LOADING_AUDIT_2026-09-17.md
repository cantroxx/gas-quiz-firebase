# 내 집 로딩 검토 — 2026-09-17

검토만 수행했으며 운영 코드 수정·배포·학생 데이터 조회는 하지 않았다.

## 운영본 대조

공개 Hosting의 home-usecases.js, home-repository.js, ranking-usecases.js는 로컬과 바이트 단위로 일치했다. index.html 전체는 미배포 상점 작업 등으로 다르지만 renderHomeView, loadHomeMemberDataFromFirestore, renderHomeMemberDataFromFirestore, showHomeView는 운영본과 일치했다.

## 확인 사항

1. 프로필 전체 갱신이 `getDailyRewardStatus` callable을 포함한 6개 작업의 Promise.all을 기다린다. 기본 프로필은 먼저 나오지만 코인·레벨 등 최신 표시가 가장 느린 요청에 묶인다. 보상 API는 회원 연결 확인 후 일일/주간 한도 문서 3개를 읽는다. 실제 Functions 지연·콜드 스타트 여부는 인증 세션 없이 측정하지 않았다.
2. 입장 시 접힌 칭호·뱃지·보유 아이템도 조회·렌더링한다. 보유 아이템 경로는 상품·에셋·인벤토리·설정 4개 공급자를 호출한다. 일부는 기존 캐시를 사용하므로 매번 4개의 네트워크 요청이 발생한다고 단정할 수 없다.
3. 프로필 데이터 완료 뒤 접힌 랭킹도 조회한다. 본인 기록 최대 500건 이후 상위 기록 최대 5개에서 추린 분야별 순위 조회를 추가한다. 화면에 펼치지 않아도 작업하며 순차 지연이 추가된다. 이는 프로필 첫 표시를 직접 막지는 않지만 불필요한 네트워크/렌더링 비용이다.
4. 내 집 모델과 보상 조회에 자체 TTL 캐시·진행 중 요청 합치기가 없다. 재진입 시 칭호/레벨/뱃지/보상 요청이 다시 시작될 수 있다. 경제·상품 등 별도 캐시는 이미 있으므로 전체 요청이 모두 중복된다는 뜻은 아니다.
5. 프로필 루트를 비운 뒤 재생성한다. 늦게 도착한 조회가 입력 중인 닉네임을 지울 수 있다. 응답의 회원/화면 세대 확인도 해당 renderHomeMemberData 경로에는 없다.

## 재현 측정

`scripts/audit/home-loading-profile.js` 실행 결과. 합성 데이터이며 실제 운영 응답 시간으로 해석하지 않는다.

- 일반 데이터 30ms / 보상 조회 600ms로 설정 → 프로필 최종 갱신 602ms.
- 1회 완료 후 2회 동시 호출 → 보상 공급자 3회 호출. 진행 중 중복 병합 없음.
- 데스크톱 Chrome 프로필 생성+레이아웃 30회: 중앙값 약 0.6ms, 최대 47ms. CSS 없는 합성 DOM의 비제한 환경으로, 모바일 전체 화면 프레임 성능을 대표하지 않는다.
- 프로필 재렌더 후 닉네임 입력 초안 유지: 실패.

## 권장 수정 순서

1. 프로필 기본 데이터와 보상 상태를 분리해 부분 갱신. 열린 입력 폼/포커스 유지.
2. 랭킹·보유 아이템은 해당 메뉴를 펼칠 때 로드. 칭호/뱃지는 프로필에 필요한 요약과 상세를 구분.
3. 회원·날짜 단위 짧은 캐시와 진행 중 요청 공유. 구매·퀴즈 완료·프로필 저장·수동 새로고침 시 무효화.
4. 회원 전환/화면 이탈/새 요청 이후의 오래된 응답 적용 방지.

현재 근거로는 데이터 대기와 불필요한 선조회가 우선 병목 후보다. 실사용 렉의 정확한 초 단위 수치와 모바일 프레임 저하는 인증된 실제 내 집 세션에서 추가 측정해야 한다.

## 수정 및 배포

후속 사용자 “수정” 요청으로 내 집 패치의 로딩 개선을 반영했다.

- `deferRewardStatus` 경로로 기본 프로필과 보상 패널 표시를 분리했다. 보상 완료 시 보상 패널만 교체한다.
- 랭킹·보유 아이템은 상세 메뉴를 펼칠 때 조회한다. 칭호·뱃지는 대표 칭호/뱃지 산출을 위해 기존 조회를 유지한다.
- 인증 UID·회원·한국 날짜별 30초 모델 캐시와 진행 중 요청 공유. 수동 새로고침·경제/상점/방 설정 초기화·퀴즈 완료 시 무효화한다. 프로필 저장 후 직접 갱신은 캐시를 우회한다.
- 프로필 응답은 회원·날짜·무효화 세대·요청 순서·내 집 노출 상태를 확인한다. 상세 응답도 회원 및 무효화 세대를 확인한다.
- 열린 프로필 편집 패널의 실제 DOM과 포커스를 보존해 초안·파일 선택이 배경 갱신에 사라지지 않게 했다. 회원이 바뀌면 기존 프로필 DOM을 비운다.
- 보상 조회 실패는 계속 확인 중으로 남기지 않고 다시 확인 필요로 표시한다.
