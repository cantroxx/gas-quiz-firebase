# 스터디 타운 난이도별 최고 기록 연동

학생별 초보·중수·고수 각 최고 기록 1개. 과목·단원·기간으로 구분하지 않는다. 한 모험의 보스 처치 수 → 완료한 방 수 → 첫 제출 정답률 → 첫 제출 정답 수 순서로 비교한다. 정답률은 정수 교차곱으로 비교하여 표시 반올림이 순위에 영향을 주지 않는다. 전부 같으면 공동 순위. 서로 다른 모험의 항목을 합치지 않는다.

## 계정·저장

- 기존 로컬 기록 유지. 연결 후 새 모험부터 서버 도전 번호 발급. 서버의 난이도·소유 학생은 도중 변경 불가.
- 퀴즈타운 로그인 팝업에서 활성 authLinks/users 연결을 확인. Firebase 로그인 토큰 대신 랭킹 전용 12시간 임의 연결 번호만 정확한 origin/source/nonce를 확인해 전달. 게임은 sessionStorage에 보관하고 서버에는 해시만 저장.
- 모든 요청에서 계정 활성 상태와 모험 소유권 재확인. 관리자 및 기존 공개 제외 학생은 랭킹 등록 제외.
- 서버 전용 studyTownSessions, studyTownRuns, studyTownRanking 경로 사용. Firestore의 기존 기본 거부 규칙 적용; 클라이언트 직접 읽기/쓰기 불가. callable로만 조회·수정. 기존 학생 데이터·경제·기존 퀴즈 랭킹 변경 없음.
- 네트워크 실패 기록은 별도 로컬 제출 대기 목록에 보존. 계정 재연결 또는 재시도 버튼으로 등록. 그만두기에서도 지금까지 완료한 기록을 제출. 답하지 않은 문제·자유 서술·연습 문제는 정답률 집계 제외.

## 검증 범위

- 랭킹 모험의 문제는 서버에서 발급하고 동일 키 재요청은 동일 문항. 객관 문항은 공유 엔진으로 서버 재채점. 최초 답안의 결과 고정, 중복 제출/종료 멱등 처리, 32문제 상한.
- 서버 트랜잭션으로 학생·난이도별 최고 기록 비교와 갱신. 전투는 로컬 실행이며 완료 방 0~24와 보스 수의 관계를 검사한다. 전체 전투 재연산이나 입력 재생 검증은 구현하지 않았으므로 클라이언트 전투 결과 조작을 완전히 방지하는 시스템은 아니다.
- 별도 주간 시험/과목별 리그/누적 플레이 점수/속도 점수는 사용하지 않는다.
- 단위 비교 검사, 합성 계정 Firestore Emulator 검사, 실제 Chrome의 서버 출제·정답·연결 실패·새로고침·재등록 검사, 기존 90문항 브라우저 검사를 수행.
- 운영 배포는 신규 studyTownAction 함수만, Hosting은 운영 manifest를 복제하여 연결 페이지와 운영 기존 랭킹용 호환 스크립트만 추가한다. 로컬 public/index.html의 동시 작업 변경은 배포하지 않으며 운영 index의 스크립트 태그만 추가한다. 통합 아지트 랭킹 화면은 동시 진행 중인 랭킹 개편 작업의 hideout-ranking-plaza.js에서 list API를 호출한다. 통합 보드가 존재하면 호환 스크립트는 주입하지 않는다. 다른 작업의 로컬 변경이나 보안 규칙을 함께 배포하지 않는다.

전체 `npm run check`는 분리 포트 검사 환경에서 통과. 합성 계정 서버·브라우저 통합, 기존 90문항 브라우저, 호환 UI 검사를 통과했다.
