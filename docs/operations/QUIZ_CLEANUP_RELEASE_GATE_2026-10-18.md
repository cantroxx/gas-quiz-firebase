# 퀴즈 정리 운영 반영 검토안 — 배포 완료

대상: [후속 실행 결과](QUIZ_CLEANUP_FOLLOWUP_RESULTS_2026-10-18.md)의 로컬 변경과 앞선 0~5단계 조회 개선. **사용자가 “배포 진행”으로 함수 5개와 Hosting 변경을 승인하여 배포 및 기술 검증을 완료했다. 데이터 삭제·Rules·인덱스·스케줄 변경은 포함하지 않는다.**

## 변경 후보

운영 소스 원본 5개를 각각 보존하고, 최초 baseline과 관련 코드가 정확히 일치하는지 검사한 후 아래 부분만 교체했다. 전체 로컬 Functions를 복사해 운영본을 덮는 후보가 아니다. 각 후보의 package.json 의존성과 package-lock.json은 현재 검증 환경과 동일하다.

| 대상 | 원격 후보에 포함하는 변경 |
| --- | --- |
| `subjectQuizAction` | 개인/과목 랭킹 조회 분리, 공통 연습 보상의 구형 이벤트 집계 호출 제거, 과목 정답의 `dailyUsage` 접근 제거 |
| `grantPracticeReward` | 공통 연습 보상의 구형 이벤트 집계 호출 제거 |
| `grantRankingCompleteXp` | 현재 추가 쓰기 0회인 구형 이벤트 집계 호출 제거 |
| `adminGetQuizQualityAudit` | 현재 문제은행 11개/명시적 보관 범위 최대 5개, 부분 실패·잘림 표시 |
| `popularQuizAction` | 공통 연습 보상의 구형 이벤트 집계 호출 제거, 검증된 이미지 14개의 파생 URL 및 카탈로그 버전 |
| Hosting | 운영 HTML에 관리자 결과 문구·숨김 탭/요청 병합 변경 적용, 운영 번들의 변경 모듈 4개와 동일 개별 소스, 새 이미지 14개 추가 |

내부 헬퍼 10개 삭제는 로컬 코드 정리다. 함수별 운영 원본에는 예전 다른 export가 있으므로 그 파일에서 도달성을 다시 증명하지 않은 헬퍼를 일괄 제거하지 않았다. 원격 후보는 위 실행 경로만 수정한다.

로컬 후보 경로: `/tmp/quiz-cleanup-followup-20261018/candidates/`. 재구성 스크립트: `scripts/maintenance/prepare-quiz-cleanup-candidates.py`. 스크립트는 검증된 원본 ZIP/baseline, 고정된 verified-snapshot 및 파일 해시를 요구하며 원격 API나 배포 명령을 호출하지 않는다. 현재 공유 파일의 하우징 쿠폰 폐지 변경은 후보에 포함하지 않는다.

Hosting 기준 릴리스: `projects/584571538436/sites/dj48-quiztown-firebase/versions/1a14e86afd5bd33d` (2026-10-18 07:22:19 UTC). HTML은 초기 baseline 대비 변경을 운영 원본에 fuzz 0으로 적용했다. 번들 4개 모듈은 운영 원본과 baseline의 정확한 일치를 확인하고 교체했다.

검증: 5개 후보의 에뮬레이터 검사 및 Hosting 구문 검사 통과. [근거·파일 해시](QUIZ_CLEANUP_FOLLOWUP_VERIFICATION_2026-10-18.json), [운영 원본 대비 index patch](QUIZ_CLEANUP_SCOPED_RELEASE_2026-10-18.patch)를 참조한다. 추가/교체 모듈과 이미지 목록은 증빙 manifest에 기록했다.

## 승인 후 반영 순서

1. 함수 updateTime/소스 generation 및 Hosting live 릴리스를 다시 확인한다. 바뀌었으면 현재 후보를 그대로 사용하지 않고 다시 대조한다. 검증된 후보 해시도 재확인한다.
2. `subjectQuizAction`, `grantPracticeReward`, `grantRankingCompleteXp`, `adminGetQuizQualityAudit`를 각각 해당 원본 기반 후보에서 선택 배포하고 읽기 액션·권한·오류 상태를 확인한다.
3. 현재 Hosting 전체 파일 manifest와 설정을 보존한 채 **후보 20파일만 교체/추가**한다. 20파일 폴더를 전체 사이트로 배포하면 나머지 파일이 사라질 수 있으므로 그렇게 실행하지 않는다. 원본 이미지와 기존 경로는 모두 유지한다.
4. 새 이미지 14개의 URL/해시/응답을 확인한 다음 `popularQuizAction`을 반영한다. 서버가 아직 없는 이미지 URL을 먼저 반환하지 않게 한다.
5. 기존/신규 세션, 개인/과목/종합 랭킹, 관리자 점검, 보상/교실 포인트·성장 퀘스트, 오류/지연을 확인한다. 학생 계정을 대신 조작하거나 보상 있는 운영 호출을 무작정 실행하지 않는다.

## 관찰과 중단 기준

- 배포 직후 오류/응답/자원 상태를 확인하고 다음 실제 수업 이용 시간대까지 관찰한다. 대표 이용이 없었다면 호출 감소나 소비 종료를 확정하지 않는다.
- 새 액션 미지원, 이미지 404, 보상/랭킹 불일치, 기존 세션 재개 실패, 새 오류 증가가 확인되면 다음 배포 단계를 중단한다. 기준 트래픽과 비교 가능한 오류/지연 자료가 없으면 ‘개선 확인’으로 표시하지 않는다.
- 원본 이미지 URL은 보존했으므로 인기 서버를 이전 카탈로그로 되돌릴 수 있다. 새 액션을 쓰는 프런트를 먼저 되돌린 뒤 서버 액션을 되돌린다. 운영본 ZIP과 이전 Hosting 릴리스를 복구 기준으로 사용한다.
- 구형 집계 쓰기 중단 기간의 진행도는 소스 롤백으로 자동 소급 복구되지 않는다. 기존 데이터와 지급 원장은 삭제하지 않는다.
- `dailyUsage`의 구형 callable/기존 문서는 유지한다. 과목 정답이 구형 잠금 해제 횟수에 더 이상 반영되지 않는 것은 사용자가 확인한 기능 종료에 따른 의도된 변경이다.

## 이후 데이터 정리

운영 쓰기 중단이 확인된 후에만 11단계의 좁은 읽기 전용 조사와 보존/복원 정책을 확정한다. 삭제 대상 ID·건수는 아직 확정하지 않았다. 12단계 삭제는 별도 manifest와 승인이 필요하다.

승인 근거: `AGENTS.md`의 “요청 없는 firebase deploy, git commit, git push를 하지 않는다”와 학생 데이터 영향 변경의 확인 규칙. 기존 ‘순차 진행’ 지시는 로컬 정리와 검증에 적용했고 운영 배포·삭제로 확대하지 않았다.

최종 결과: [배포 기록](QUIZ_CLEANUP_DEPLOYMENT_2026-10-18.md). 최신 하우징 릴리스를 보존해 재구성했으며, 랭킹 함수의 확장 설정은 기존 실효 기본값 100을 명시했다. 실제 이용 관찰과 데이터 삭제는 미완료·미실행이다.
