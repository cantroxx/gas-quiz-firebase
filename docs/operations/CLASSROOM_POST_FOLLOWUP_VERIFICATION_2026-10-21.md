- 실제 그라운드 내보내기 확정·기준 시각 동결·학생 대응표 승인.
- 씨앗 가격/수확 보상/복권 회차 및 원본 경제 정책의 최종 선택과 실제 원본 대조.
- 원본 잔액·기금·예금·소유물·성장·신청·개인 기록·주식·복권의 누락 없는 수량/금액 대조.
- 실 기기 터치·교실 뒤쪽 가독성 확인(기본 해상도 검증과 구별).
- 배포 직전 현재 운영 버전과 후보 전체 대조, 전체 `npm run check`, 인덱스 준비, 복구 리허설 결과 승인.
- 최종 총점검 완료 후에만 배포·실제 이전을 별도 지시 범위에서 실행. 이번 요청은 배포 금지.

### 거래와 권한 검사

- 루틴: 일일·기간형, 항목별 부분 완료, 같은 항목 재전송, 지급 후 체크 해제 차단, 이미 기록한 정책 변경 차단, 비활성화 허용.
- 급여: 두 직업의 독립 월급, 평가+세금, 같은 직업/월 중복 차단, 새 배정 ID로 우회 불가, 기존 급여 경로와 교차 재지급 차단.
- 예금·환전: 원금·약정 이자·중도해지 비용, 반복 정산 차단, 잔액 부족 시 지갑/기금 변경 없음, 수수료 원장 합계 일치.
- 농장·상점: 씨앗 구매·소비·시간 전 수확 거부, 동시 수확 1회, 소유 스킨만 적용, 쿠폰 교사 사용 확인, 응답 유실 뒤 같은 요청으로 재확인해도 재구매 없음.
- 복권: 1~100 검증, 학생당 1장, 교사의 판매 조기 마감, 마감 전 추첨 거부, 동시 추첨 1회, 공동 당첨 분할, 소수 분할 잔액 반환, 당첨자 없는 회차의 예약금 반환.

### 조회 비용 검사 해석

`board-performance.test.js`는 과거 보관 4,000건 + 과거 진행 2,000건을 넣었다. 변경 전 조회 구조의 문서 반환량 하한은 12,044건, 현재 최초 호환 조회는 2,044건, 같은 회차 반복 조회는 44건이다. 인덱스 비용·네트워크 지연·운영 청구액을 측정한 값은 아니다. 캐시가 차갑거나 쓰기 뒤 무효화되면 최초 비용이 다시 발생한다. 과거 형식의 회차 보완은 실제 이전/운영 데이터 변경에 해당하므로 이번에 수행하지 않았다.

## 최종 총점검으로 넘길 구체적 입력과 순서

아래 항목은 실패를 숨겨 완료 처리한 로컬 검사 항목이 아니라 실제 운영 반영을 위한 미실행 조건이다.

1. **원본 동결·대상 확정**: 추출 시각, 교사 제외, 학생 고유 ID 매핑, DJ48에만 있는 학생 처리, 누락 가격/동명 품목 결정. 지금까지의 합성 자료를 실 원본으로 대체한다.
2. **원본 전체 대조**: 분류별 건수, 활동 본문·첨부, 지갑, 예금 원금/이자, 기금, 소유권/효과, 성장/기지급 보상, 신청·관찰·일기, 주식 수치, 미추첨 복권을 모두 대조한다.
3. **경제 정책 확정**: 씨앗 가격/기간/수확량과 스킨 대응, 기존 농장 효과의 보관/대체, 급여 세금의 원본 반올림 방식, 잔액과 XP의 분리, 진행 중 예금·복권·신청 승계 계획. 실제 원본이 없는 항목은 추정하지 않는다.
4. **원본 파일 보관 필요성**: 현재 압축 미리보기로 대체하면 안 되는 원본을 확정하고, 필요 시 비공개 Storage 경로·보관 기간·본인/교사 열람을 추가 구현/검증한 뒤 총점검 판정을 내린다. 현재는 오프라인 원본 무결성 검증과 보관 설계까지다.
5. **후보 버전 동결**: [해시 목록](classroom-board-2026-10-21/followup-release-manifest.json)과 실제 파일을 다시 비교한다. 기존 미커밋 변경이 섞인 공유 파일의 릴리스 범위를 분리하고 운영 Functions·인덱스 상태를 대조한다.
6. **최종 전체 검사**: 확정 후보에서 `npm run check`, 실제 원본 미리보기, 건수/금액/권한 대조, 장애·재실행·복구 리허설과 현장 전자칠판 점검을 수행한다. 소스가 바뀌면 해당 검사 결과와 해시를 갱신한다.
7. **결과 보고 후 실행**: 최종 총점검 결과, 실제 변경 전후 금액/대상/건수, 복구안을 사용자에게 제시한다. 이후 지시받은 배포·이전 범위만 실행한다. 이번 요청에서는 둘 다 실행하지 않는다.

복구 리허설의 최소 기준: 이전 직전 스냅샷과 원본 해시 보존, 배치별 원본 ID/변환 해시/대상 키 기록, 지급 경로를 거치지 않는 잔액·과거 기록 반영, 재실행 시 같은 해시는 건너뛰고 다른 해시는 중단, 반영 후 지갑·기금·미지급 채무 합계 대조. 이전 뒤 거래가 발생했다면 원본 스냅샷으로 단순 덮어쓰는 자동 복구를 금지하고 후속 거래까지 대조한다. 이 리허설과 실제 실행기는 원본·최종 범위 확정 후 준비하며 지금 운영에 실행하지 않았다.

## 최종 총점검 결과 — 2026-10-21

### 판정 범위

로컬 기능 검사와 운영 상태 조회를 수행했다. **실제 데이터 이전 준비는 보류**다. 동결된 전체 원본·대상 스냅샷과 계정/품목 매핑이 없고, 원본 화면에서 진행 중 계약이 실제 확인됐기 때문이다. 화면의 현재 합계나 합성 예제 통과를 전체 이전 대조 완료로 간주하지 않는다.

배포, 운영 학생 데이터 쓰기, 원본 승인·반려·추첨, 실제 이전, commit/push는 하지 않았다. 원본 학급 설정과 자산/포인트 요청 화면은 조회만 했고, 그라운드 탭은 기존 퀘스트 화면으로 돌려놓았다.

### 자동 검사와 이번 보완

### 원본 확보에 관한 사용자 추가 확인

사용자가 별도 내보내기 자료가 없음을 확인했다. G-01은 파일 경로 응답 대기가 아니라 **원본 확보 방법부터 정해야 하는 상태**다. 우선 서비스가 제공하는 내보내기·백업 경로를 확인하고, 제공되지 않는다면 로그인된 관리자 화면에서 읽기 전용으로 확보할 수 있는 항목과 누락되는 항목을 구분해야 한다. 화면에서 수집한 일부 수치만으로 전체 백업·고유 ID 대응·원본 무결성을 충족했다고 판정하지 않는다. 원본 확보 전 배포·실제 이전·미처리 신청 승인·복권 추첨은 진행하지 않는다.
