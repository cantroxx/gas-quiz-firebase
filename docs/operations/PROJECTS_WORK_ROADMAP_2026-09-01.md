## 운영 원칙

1. 1~12단계를 순서대로 진행한다. 선행 단계가 끝나지 않았으면 뒤 단계의 대규모 개발을 시작하지 않는다.
2. 각 게임은 해당 폴더를 별도 Codex 프로젝트로 열어 작업한다.
3. 작업 전 상위와 프로젝트별 `AGENTS.md`를 읽는다.
4. 미커밋 변경을 먼저 분류하고, 기존 사용자 변경을 덮어쓰지 않는다.
5. 요청 없는 commit, push, deploy는 하지 않는다.
6. Firebase 규칙·Functions·학생 데이터 변경은 영향과 검증 방법을 먼저 설명하고 사용자 승인을 받는다.
7. 파일·폴더 삭제와 공개 에셋 추가는 사용자 확인 후 진행한다.
8. 각 단계가 끝나면 이 문서의 상태와 완료 기록을 갱신한다.

### 완료 기준

- 모든 활성 공개 프로젝트에 실제 프로젝트 내용의 README 존재
- 일반 Vite 템플릿 문구 제거
- 배포 주소와 로컬 원본 관계 확인
- 새 작업자가 README와 `AGENTS.md`만으로 실행·검증 가능

## 단계 완료 기록

각 단계 완료 시 아래 형식으로 추가한다.

```text
- YYYY-MM-DD · 단계 N 완료
  - 변경한 저장소:
  - 완료한 항목:
  - 검증:
  - 커밋·배포:
  - 남은 위험:
```

## 다음 작업 선택 규칙

기본 다음 작업은 **1단계 작업 기준점 저장**이다. 다만 commit 권한이 없으면 1단계를 `사용자 확인 필요`로 유지하고, 사용자에게 정확한 저장소·스테이징 파일·커밋 목적을 제시한 뒤 승인을 기다린다.

앞 단계가 승인 대기일 때 뒤 단계의 읽기 전용 분석은 가능하지만, 상태를 바꾸는 구현은 시작하지 않는다.
