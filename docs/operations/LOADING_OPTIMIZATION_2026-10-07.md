# 코디 데이터 경량화·교실 조회 병렬화 — 2026-10-07

사용자 “진행” 요청에 따라 앞서 제안한 두 개선을 구현·검증·배포했다. 새 교실 디자인과 다른 작업의 변경을 보존했다. 포인트·가격·상품 자격·학생 공개 범위·쓰기 처리 코드는 바꾸지 않았다.

## 운영 상품 목록 실측

같은 컴퓨터의 Chrome에서 배포 전후 각각 3회, 다운로드 4Mbps / 지연 80ms / CPU 4배 감속으로 공개 JSON 4개를 병렬 로드했다. 실제 운영 파일 다운로드와 JSON 파싱까지 측정했다. 로그인·잔액 조회·전체 상점 렌더링·첫 사이트 접속 시간은 포함하지 않는다.

| 항목 | 전 | 후 | 변화 |
| --- | ---: | ---: | ---: |
| 목록 준비 시간 중앙값 | 3,635ms | 466ms | 약 87.2% 감소 |
| 목록 전체 실제 전송량 중앙값 | 1,718,023바이트 | 135,666바이트 | 약 92.1% 감소 |
| 무거운 상품 JSON 원본 크기 | 4,721,086바이트 | 775,072바이트 | 약 83.6% 감소 |

시간 표본: 이전 3,758.9 / 3,605.8 / 3,635.2ms, 이후 465.6 / 507.7 / 446.9ms. 이 조건에서 상품 목록 대기는 약 3.17초 줄었다. 학교 네트워크·실제 학생 기기의 전체 상점 진입 시간이 같은 비율로 줄었다는 뜻은 아니다. Hosting 실제 전송은 Brotli 압축과 헤더를 포함한다.

## 코디 변경

- 원본 `public/coordi-shop/data/verified-top50.json`을 유지하고 `verified-top50-display.json`을 생성한다. 원본 검토 기록과 검증 해시를 삭제하지 않는다.
- 화면이 소비하는 `itemsByCategoryGender`를 그대로 보존하고 각 항목의 검증용 `hash`·`imageBytes`만 제외한다. 상품 이름·코드·썸네일·인기도·정렬·성별·필터용 필드·알 수 없는 확장 필드는 유지한다. 인물 미리보기의 `look.hash`와는 무관하다.
- 화면 로더를 새 파일로 연결하고 HTML→브리지→스크립트 버전을 갱신했다. JSON의 기존 `no-store` 정책은 유지한다.
- `scripts/build-coordi-display-catalog.js`를 `npm run check:static`에 연결했다. 원본을 수정하면 화면용 산출물을 다시 생성하며, `--check`로 일치 여부를 확인한다.
- 2,689개 표시 행 전체에 대해 필드·순서·상품 식별자·서버 상품 존재·자격 필터·정렬 결과의 일치를 검증했다. 원본 파일의 해시도 보존한다.

## 교실 변경

`getClassroomEconomyBoard`의 권한 검사가 완료된 뒤 시작하는 독립적인 조회 20개를 하나의 병렬 대기로 합쳤다. 기존의 여러 순차 대기 묶음 때문에 뒤의 조회가 앞의 응답을 기다리던 시간을 줄인다.

실제 배포 소스를 내려받아 읽기 구간이 수정 전 코드와 같음을 확인했다. 해당 구간만 바꾼 별도 배포 후보를 만들었으며 나머지 운영 코드와 의존 파일은 유지했다. 학생·교사의 모든 쿼리 경로, 필터, 제한 개수와 각 응답의 연결이 이전과 같음을 비교했다. 읽기 수 자체는 20건으로 같다. 첫 조회가 실패해도 이미 시작한 다른 병렬 읽기는 완료될 수 있어, 실패 상황의 읽기 수가 기존 순차 처리보다 많아질 수 있다.

권한 없는 호출·잘못 연결된 계정·다른 교실 접근에서는 콘텐츠 조회가 시작되지 않음을 합성 테스트로 확인했다. 조회 실패는 기존처럼 오류로 전달한다. 미션 달성일 등 기존 쓰기 로직은 수정하지 않았다. 운영 학생 계정으로 경제 조회 함수를 호출하지 않았다.

| 합성 조건: 각 읽기에 20ms | 기존 조회 구간 | 개선 조회 구간 |
| --- | ---: | ---: |
| 학생 | 212ms | 21ms |
| 교사 | 211ms | 21ms |

이는 인증·콜드 스타트·실제 Firestore·응답 구성·화면 렌더링 시간을 포함하지 않는 단일 비교다. 전체 교실 사용 가능 시간이 90% 단축됐다고 해석하지 않는다. 학생별 레벨 문서 추가 조회와 탭별 데이터 분리는 아직 남아 있다.
