# 다음 실행 게이트: 구형 퀘스트 집계 쓰기 중단

상태: **사용자의 “이어서 작업 진행” 후 로컬 적용·검증 완료. 운영 배포 없음.**

기존 [단계별 실행 정본](QUIZ_CLEANUP_EXECUTION_PLAN_2026-10-18.md)의 0~4단계에 이어, 사용자의 계속 진행 지시에 따라 5단계 중 아래 첫 변경을 로컬 적용·검증한다. 적용 전에 현재 Functions 소스가 검토용 patch 작성 시 SHA-256과 동일함을 확인했다.

## 제안 변경

[검토용 patch](QUIZ_CLEANUP_EVENT_WRITE_PROPOSAL_2026-10-18.patch)는 `functions/index.js`의 다음 두 호출만 제거한다.

1. `grantPracticeRewardInTransaction` → `updateEventQuestProgressForKinds`: 과거 `eventQuestProgress`에 더 이상 정답을 집계하지 않는다.
2. `grantRankingCompleteXp` → 동일 헬퍼: 현재 정의상 쓰기 0회인 구형 경로도 함께 끊는다.

기존 `eventQuestProgress` 데이터, `growthQuestProgress`를 사용하는 현행 일일/주간 퀘스트, `rewardLogs`, 코인/XP/보상 한도/교실 포인트 반영, 지급 중복 방지, 현재 랭킹 기록은 보존한다. 헬퍼 정의·구형 보상 이력·시즌 설정을 이 변경에서 삭제하지 않는다. `dailyUsage`도 이번 제안에 포함하지 않는다.

영향: 구형 이벤트 화면/직접 조회가 남아 있다면 그 화면의 과거 퀘스트 진행도가 더 이상 증가하지 않는다. 현재 타운은 새 성장 퀘스트를 반환하므로 그 진행도는 계속 증가해야 한다. 실행 전 운영 Functions 소스와 현재 로컬 구현을 대조해야 한다.

## 로컬 구현·검증 절차와 운영 전 조건

1. patch 생성 당시 소스와 현재 파일을 다시 대조하고 충돌 없이 두 호출만 제거한다.
2. 에뮬레이터에서 과목별 정답·일반 연습·인기 완료 보상·랭킹 정상 완료·중복/동시 요청을 실행한다.
3. 변경 전/후 코인·XP·일일/주간 제한·교실 포인트·현행 성장 퀘스트 결과를 비교한다. 구형 진행도 문서의 갱신은 0회여야 한다.
4. 과거 `eventQuestProgress` 합성 문서가 그대로 남는지, 지급 원장과 처리 표식이 유지되는지 확인한다.
5. 전체 검사 통과 후 배포할 함수 목록과 최신 배포 소스의 차이를 별도 보고한다. 이 승인만으로 배포하지 않는다.

복구: 운영 데이터를 지우는 변경이 아니므로 소스 롤백으로 이후 구형 집계를 다시 켤 수 있다. 중단 기간의 과거 진행도를 자동으로 소급 복구할 수 있다는 뜻은 아니다. 따라서 운영 반영 전 구형 화면/외부 소비자가 없음을 확인해야 한다.

## 이번에 확인한 것과 아직 하지 않은 것

- 검토용 patch 생성 및 JavaScript 구문 검사 통과 후, 두 호출만 로컬 소스에서 제거했다.
- `npm run check:cleanup-rewards` 통과. 일반/과목/인기 보상 한도와 중복 방지, 랭킹 완료, 성장 트리거 재시도 및 퀘스트 수령을 확인했다. 구형 합성 문서의 updateTime과 문서 수가 유지됐다. 교실 포인트 변경 전후 독립 비교와 운영 Functions 소스 대조는 별도 운영 전 점검으로 남긴다.
- 전체 검사는 마지막 서버 보완 전 통과했고, 마지막 보완 후 관련 에뮬레이터 검사 및 정적 검사를 통과했다. [검증 증빙](QUIZ_CLEANUP_VERIFICATION_2026-10-18.json)을 참조한다.
- 운영 데이터 삭제 manifest, 이미지 변환, 미참조 함수 제거, `dailyUsage` 중단은 별도 후속 단계다.

계속 진행 지시는 이 patch의 **로컬 적용·에뮬레이터 검증** 범위에 적용한다. 운영 데이터 삭제/배포 승인으로 확대하지 않는다. 승인 경계 근거는 저장소 `AGENTS.md`의 “보안 규칙이나 학생 데이터에 영향을 주는 변경은 영향과 검증 방법을 먼저 설명하고 사용자 확인 후 진행한다”이다.

후속 항목의 실행 순서·완료 기준·승인 범위는 [6~12단계 후속 계획](QUIZ_CLEANUP_FOLLOWUP_PLAN_2026-10-18.md)에 통합했다.

후속 실행에서 교실 포인트 전후 비교와 운영 소스 대조를 완료하고, 사용자 종료 확인 후 과목 `dailyUsage` 중단도 로컬 검증했다. 최신 승인 경계는 [운영 반영 검토안](QUIZ_CLEANUP_RELEASE_GATE_2026-10-18.md)이다.
