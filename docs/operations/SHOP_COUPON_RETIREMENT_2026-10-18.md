# 상점 구매 쿠폰 10장 일괄 조정·가구 쿠폰 폐지

## 승인 범위

사용자 지시: 현재 모든 인원의 마을 상점 구매 쿠폰을 정확히 10장으로 맞추고 추가 배급을 하지 않는다. 내 방 가구 쿠폰은 폐지한다. 하보 인테리어 재연결은 하지 않는다.

- `coordiProfiles.purchaseCoupons`: 기존 회원 전원 10장으로 **설정**한다. 10장을 더하지 않는다.
- 기본 20장 자동 지급을 없앤다. 이후 신규 회원·쿠폰 필드 없는 회원은 0장이다. 소비 후 재접속·염색·장착으로 충전되지 않는다.
- `userEconomy`의 가구 쿠폰 잔액과 지급 표식을 제거한다. 기존 callable·예약 함수는 호환 응답만 하고 지급·잔액 쓰기는 하지 않는다.
- 구형 클라이언트의 가구 쿠폰 결제도 서버에서 거부한다. 가구 쿠폰 화면 표시·사용 버튼·안내·접속 시 지급 호출을 제거한다.
- DJ코인, 보유 아이템, 코디, 구매 내역, 학생 계정, 보안 규칙은 변경하지 않는다.

## 안전한 적용 방식

작업 트리에 여러 미배포 변경이 있어 현재 운영 소스를 내려받아 쿠폰 변경만 별도 후보에 적용했다. 대상은 `coordiShopAction`, `claimHousingDailyCoupon`, `resetHousingWeeklyCoupons`, `purchaseHousingItem` 네 함수다. 각 함수의 기존 운영 소스를 따로 보존하며 배포 전 updateTime, 배포 후 소스 해시와 서비스 설정을 대조한다.

Hosting은 현재 릴리스에서 `/index.html`, `/housing/index.html`, `/housing/app.js`, `/housing/housing-data.js` 네 파일만 바꾸고 나머지 파일·설정을 보존한다. 삭제된 DOM과 이전 스크립트가 섞이지 않도록 가구 스크립트 캐시 버전도 갱신한다.

백업: Git 제외 경로 `exports/shop-coupons-20261018/backup.json`, 권한 0600. 회원 ID, 변경 대상 쿠폰 필드, 문서 updateTime만 저장한다. 이름·비밀번호는 읽거나 저장하지 않는다.

`scripts/maintenance/normalize-shop-coupons.js`는 기본 실행 시 백업과 집계 미리보기만 한다. `--commit`은 서버 함수 반영 확인 후 318개 문서 작업을 하나의 원자적 배치로 실행한다. 회원 목록이나 문서 updateTime이 달라지면 전체 작업을 중단한다. `manual-10-20261018` 표식으로 재실행해도 이미 사용한 쿠폰을 재충전하지 않는다. 과거 상태 복구는 백업과 현재 소비 상태를 대조한 별도 작업으로 다룬다.
