# 이벤트 광장 로딩 개선

사용자 요청: ‘이벤트 광장 렉이랑 로딩도 해결하자.’

## 확인된 원인

- `showEventView`가 재진입할 때마다 진행도 카드를 지운 뒤 운영 설정을 기다리고, 그 후 `getEventProgress`를 호출했다. 기존 캐시가 있어도 빈 화면을 거쳐 카드를 다시 만들었다.
- `forceRefresh`는 진행 중인 요청도 무시하므로 연속 갱신 시 callable이 중복됐다. 오래된 요청이 늦게 끝나면 최신 요청·캐시를 덮을 여지도 있었다.
- 진행도 캐시는 무기한이며 회원·인증 계정·한국 날짜를 구분하지 않았다. 퀴즈 종료 시에도 명시적으로 무효화하지 않았다.
- 조회 오류 때 실제 기록 대신 고정 예시 퀘스트를 표시하는 경로가 있었다.
- 서버 `getEventProgress`는 운영 설정과 연결 회원 확인 이후 퀘스트 진행 문서·보상 이력·시즌 설정을 읽는다. 서버 첫 실행 지연이나 실제 학교 네트워크에서의 응답 시간은 이번 검사에서 측정하지 않았다.

## 변경

- 운영 설정과 진행도 조회를 동시에 시작한다. 진행도 callable의 기존 서버 회원·운영 설정 검증은 유지된다.
- 이벤트 입구에 포인터/키보드 포커스가 도착하면 조회와 광장 이미지 로드를 시작한다. 로그인 화면에서는 미리 읽지 않는다. 입구 접근과 실제 진입은 같은 진행 요청을 공유한다. 실패 시 재시도 폭주 방지를 위해 입구 선조회 시도 간격은 10초다.
- 60초간 같은 회원의 진행도를 재사용한다. 만료 후에는 기존 카드를 유지한 채 갱신한다. 같은 데이터면 카드 DOM을 다시 만들지 않아 깜빡임·포커스 손실을 줄인다.
- 새로고침 버튼·조회 상태·오류 재시도를 제공한다. 실패 시 마지막 정상 기록을 유지하며, 정상 기록이 없으면 예시 퀘스트 대신 오류를 표시한다.
- 계정/회원/한국 날짜별로 캐시를 분리하고 보상 수령·퀴즈 완료/이탈·전체 새로고침 시 무효화한다. 무효화 전 요청은 현재 캐시나 화면을 덮을 수 없다. 강제 갱신도 같은 진행 요청에 합친다.
- 코인 지급, 보상 판정, 퀘스트 조건, 학생 데이터, 서버 코드 및 보안 규칙은 수정하지 않았다.

## 검증

- `tests/application/event-usecases.test.js`: 기존 보상 흐름과 60초 만료, 자정, 계정 전환, 강제 갱신 중복 제거, 무효화 후 늦은 응답 검증.
- `scripts/smoke/event-loading-browser.js`: 실제 HTML 진입 함수를 사용해 운영 설정 응답 전 진행 조회 시작, 재진입의 추가 callable 0회, 기존 카드 노드 유지, 연속 갱신 2회에 callable 1회, 실패·재시도, 입구 선조회 재사용, 계정 전환 중 응답 차단, 모바일 가로 넘침 검증. 합성 데이터만 사용했다.
- 독립 포트 복사본 `/tmp/hideout-check`에서 전체 `npm run check` 통과. 배포 후보의 실제 번들·HTML에서도 전용 브라우저 검사 통과.
- 최초 후보 준비 후 운영 버전이 변경되어 배포 보호 검사가 중단했다. 새 운영본 `c23af5e4d7827b54`에서 후보를 다시 만들고 전용 브라우저 검사를 재통과했다. 이벤트 관련 6개 파일만 교체했고 나머지 파일 397개·다른 번들 모듈·Hosting 설정 보존을 확인했다.

배포 버전 `0537d1d516333df2`, release `1789604056907000`.
배포 후 6개 파일의 SHA-256이 검증 후보와 일치했고 운영 공개 화면 브라우저 검사도 통과했다.

이번 검증의 수치는 호출 수와 DOM 재사용이다. 실제 첫 진입의 초 단위 속도 향상이나 서버 콜드 스타트 제거를 주장하지 않는다.
