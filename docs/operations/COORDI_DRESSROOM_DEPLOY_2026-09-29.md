# 코디 상점·학생 무료 드레스룸 운영 배포

2026-09-29, 사용자의 배포 및 드레스룸 추가 요청으로 반영했다.

## 학생 이용 방법

관리자 기능 관리의 `상점 열기`를 켜고 저장하면, 로그인한 활성 학생이 상점의 `드레스룸 · 무료로 입어보기` 또는 `코디 상점 열기`로 들어간다. 배포 직후 설정을 읽어 확인한 결과 `shopEnabled:true`였다. 이번 작업은 해당 설정을 변경하지 않았다.

상점이 닫히면 학생의 입장·상품 조회·구매·장착·염색·미리보기 요청을 차단한다. 관리자는 닫힌 상태에서도 점검할 수 있다. 미리보기 캐시를 반환하기 전에도 회원 연결·활성 상태·상점 설정을 확인한다.

드레스룸은 보유 여부와 관계없이 입어보기, 랜덤 코디, 피부와 의상 염색 미리보기를 제공한다. 구매·장착·염색 저장 버튼을 숨기고 거래 호출도 차단한다. 상점 탭으로 이동하면 현재 입어본 코디를 유지하며, 구매는 별도 확인 후 진행된다. 미리보기 완료 메시지는 실제 장착 저장과 혼동하지 않도록 `미리보기 반영됨`으로 변경했다. 실제 장착은 기존 coordiProfiles에 보유 상품만 저장한다.

## 배포 내용

- 고유 상품 1,632종, 남녀 표시 2,689행. 상의 213종·하의 167종.
- 마스터 91종·스페셜 186종·피부 37종·투명 8종 유지.
- 확인된 보상 32종과 저사용량 일반 상·하의 98종 제외. 능력치 옵션 이력이 있는 유료 액세서리 4종은 뒤쪽으로 정렬.
- 어비스 헤어 등 지원되지 않는 대체 렌더로 전환하지 않고, 이미지 실패 안내와 재시도를 제공.
- 새 서버 함수 `coordiShopAction`, 기존 `renderCoordiShopPreview` 갱신. 둘 다 asia-northeast3, Node 22, ACTIVE 확인.
- 운영 코디 미리보기 함수 소스를 기준으로 구매 서비스와 렌더 접근 검사를 연결했다. 회원 활성·연결 검사 공통 함수는 운영본과 로컬의 일치를 단언했다. 다른 함수는 배포하지 않았다.
- 운영 Hosting을 복제하고 코디 경로·상점 진입 함수·번들 캐시 버전만 반영했다. 기존 상점의 다른 기능과 Hosting 설정은 보존했다.
- Hosting 이전 버전: `8745580fe255b98c`
- Hosting 새 버전: `efde6220ada964b8`
- Release: `1790679638391000`
- 보안 규칙·인덱스·운영 설정·학생 실데이터는 직접 수정하지 않았다. 테스트 구매는 데모 환경에서만 했다.

## 검증

- `npm run check` 전체 통과. 기본 에뮬레이터 포트가 다른 작업과 겹쳐 임시 설정으로 Firestore 18681, Storage 19299를 사용했다. 저장소 설정은 변경하지 않았다.
- 실제 배포 후보를 데모 Firestore에 연결해 학생/관리자/미인증/미연결/비활성 접근, 상점 닫힘, 캐시 조회 전 권한 검사, 무료 미리보기의 잔액·프로필·영수증 무변경, 동시 구매 중복 차감 방지, 보유품 장착, 제외 상품 구매 차단을 확인했다.
- 브라우저: 드레스룸 입장, 미보유 상품 입어보기, 랜덤 코디, 염색 미리보기, 거래 요청 0건, 상점 전환 시 코디 유지, 390px 화면, 구매·장착·복원 통과.
- 실제 Hosting 후보의 상점 진입 함수로 학생용 두 버튼, 닫힘 시 iframe 제거, 관리자 예외를 확인했다.
- 배포 후 운영 HTML·번들·상점 모듈·드레스룸 파일·전체 상품 JSON·어비스 이미지의 해시를 후보와 대조했다.
- 관련 함수 2개 ACTIVE, 비로그인 호출 HTTP 401 확인. 운영 공개 셸 브라우저 검사도 통과했다.
- 실제 학생 계정으로 결제하거나 장착하는 운영 테스트는 하지 않았다. 권한·결제·저장은 합성 계정과 실제 데모 트랜잭션으로 검증했다.
