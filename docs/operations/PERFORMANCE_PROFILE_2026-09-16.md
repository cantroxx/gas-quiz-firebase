# 로딩 개선과 내 정보 UI

## 적용 범위

프런트엔드 변경. 사용자 전체 배포 요청으로 2026-09-16 Hosting에 반영했다. 운영 데이터 수정 없음. 상점/하우징 프로토타입 유지.

1. 마을·학교·이벤트·랭킹 원본 PNG를 동일 해상도 WebP(quality 84)로 인코딩하고 운영 화면 참조를 교체. 원본은 보존.
2. 숨겨진 이벤트·랭킹 배경은 `loading="lazy"`로 진입 시 로드.
3. 게임별 랭킹 5개는 로그인 때 미리 조회하지 않고 실제 하위 패널을 열 때 조회. 공통 `ranking-visibility.js`가 패널 열림/교체를 감지한다. 진행 중 요청 보호와 수동 새로고침을 유지한다. 기존 퀴즈 랭킹 집계·저장 경로는 그대로다.
4. 내 정보는 `profile-view.css`로 종이 수첩 분위기 적용. 프로필·칭호·코인·레벨·설정을 앞에 배치하고 보상/오늘의 퀴즈와 보유 항목을 이어 배치. 기존 ID와 클릭 처리 유지.

## 측정

| 배경 | 이전 PNG bytes | 적용 WebP bytes |
|---|---:|---:|
| 마을/로그인 | 3,229,947 | 415,834 |
| 학교 | 2,699,709 | 258,202 |
| 랭킹 | 2,461,985 | 207,506 |
| 이벤트 | 2,586,364 | 241,082 |
| 합계 | 10,978,005 | 1,122,624 |

배경 파일 합산 용량 약 89.8% 감소. 이는 파일 크기 비교이며 실제 접속 시간 90% 단축을 의미하지 않는다. 원본을 보존했으므로 Hosting 전체 저장 용량은 줄지 않는다.

로그인 상태를 모사한 브라우저에서 선택하지 않은 게임 랭킹 조회 0건, 온라인 탭 진입 시 낱말 랭킹만 1건, 구름탑/마블 선택 시 각각 해당 데이터만 1건을 확인했다. 마블 수동 새로고침 시 추가 1건. 초기 로그인 화면에서 두 광장 이미지 요청이 없음을 확인했다.

## 검증

- `npm run check:static`
- `npm run test:application`
- `npm run test:infrastructure`
- `node scripts/smoke/profile-performance-browser.js`: 실제 렌더러/컨트롤러 + 가짜 읽기 API. 닉네임 저장 위임, 설정 열기/닫기, 비밀번호 입력 표시, 모바일 390px 넘침 없음, 선택한 랭킹만 조회, 새로고침.
- `node scripts/smoke/plaza-storybook-browser.js`: 광장 UI 회귀 검사.

위 검사 통과. 브라우저 캡처는 샘플 프로필이다. 운영 서버 응답시간, 실제 학생 기기에서의 장시간 게임 프레임률은 측정하지 않았다. 전체 사이트의 모든 지연이 해결되었다고 판단하지 않는다. 다음 운영 확인에서는 느린 화면의 네트워크 요청시간과 프레임 지연을 구분해 추가 분석한다.
