# 분수 피자집 — 학급 단원 평가

## 구현 범위

- 독립 게임 화면: `public/pizza-assessment/` (학생 답안은 기존 회원·랭킹·경제와 분리, 총괄 관리자만 기존 퀴즈타운 인증·권한 연동)
- 4학년 2학기 1단원 분수의 덧셈과 뺄셈, 25문항 × 4점 = 100점
- 교사: 학교, 학년, 반, 마지막 번호(1~60)로 평가 회차 개설
- 학생: 학교, 학년, 반, 번호로 입장. 이름·비밀번호는 수집하지 않음
- 같은 학급의 활성 회차는 하나. 채점 후 ‘학급 종료’를 누르면 새 회차 개설 가능. 입장/답안 저장 기한은 개설 후 12시간이며 이후에도 교사 채점·기존 결과 확인 가능
- 교사: 입장·답안 수·최종 제출 현황, 입장 초기화, 채점하기, 결과받기(PDF)
- 학생: 분수/대분수 입력, 선택형 원리 문항, 토핑 조작, 굽기→포장→배달, 문항 이동·수정, 최종 제출, 교사 채점 대기
- 채점 공개 후 25개 결과 장면(일시 정지/다음/전체 결과), 점수, 유형별 성취, 오답별 정답·간단한 풀이
- 교사·학생 상태는 4초 간격으로 동기화. 채점 시작 수신 시간은 네트워크 지연을 포함하여 달라질 수 있음
- 소리 기본 꺼짐, 키보드 조각 조작, 동작 줄이기 설정 반영, 390px 모바일 레이아웃

## 학급과 권한

`pizzaAssessmentAction` Callable 하나가 아래 별도 컬렉션만 사용한다.

| 위치 | 내용 |
|---|---|
| `pizzaAssessmentDirectory/{학교·학년·반 SHA-256}` | 활성 회차 ID, 만료 시각 |
| `pizzaAssessmentSessions/{회차 ID}` | 학급, 교사 토큰 해시, 상태, 문항 버전·스냅샷, 확정 보고서 |
| `pizzaAssessmentSessions/{회차 ID}/students/{번호}` | 학생 토큰 해시, 25개 답안, 제출 여부, 변경 번호, 갱신 시각 |
| `pizzaAssessmentDeletions/{회차 ID}` | 총괄 관리자 삭제 이력·이전 토큰 재사용 차단, 답안·점수 미포함 |

교사·학생 입장은 로그인 계정을 새로 만들지 않는 회차 전용 구조다. 브라우저에서 생성한 256비트 임의 토큰을 Callable로 전달하고 서버에는 해시만 저장한다. 교사 토큰은 개설·관리·채점·보고서, 학생 토큰은 특정 회차·특정 번호의 답안만 허용한다. 교사라는 실제 신원을 인증하는 구조는 아니다. 교사가 학급을 개설하고 학생 번호를 확인하는 교실 운영을 전제로 한다. 별도의 총괄 관리자 기능은 퀴즈타운 Firebase Auth와 기존 총관리자 권한을 사용한다.

학급명만으로 점수/명단을 조회할 수 없고, 학생에게 정답/해설은 채점 전 전달하지 않는다. Firestore 클라이언트 직접 접근은 기존 최종 deny 규칙으로 거부한다. 이 작업에서는 `firestore.rules`를 수정하지 않았다. 다른 작업의 기존 미커밋 rules 변경은 그대로 보존했다.

교사 관리 권한과 학생 재입장 권한은 해당 브라우저 localStorage에 보관한다. 다른 교사 컴퓨터로 자동 이전하지 않는다. 교사는 같은 기기의 ‘관리 화면 이어가기’를 이용하고, 공용 기기는 PDF를 받은 뒤 학급 종료→관리 연결 지우기를 사용한다. 학생 기기 변경은 교사의 ‘입장 초기화’로 기존 토큰을 무효화하고 새 입장을 허용하며, 저장된 답안은 유지한다. 이는 학생 기록 삭제 기능이 아니다.

서버는 같은 번호의 동시 입장을 트랜잭션으로 막고, 최종 제출/채점 후 답안 변경을 거부한다. 문항과 정답은 개설 당시 스냅샷을 사용하여 이후 문항 편집으로 기존 점수가 변하지 않는다. 학급 종료는 활성 목록에서만 제외하며 평가 결과를 자동 삭제하지 않는다. 총괄 관리자는 아래 기능으로 특정 회차를 영구 삭제할 수 있다. 자동 보존 기간과 일괄 정리 작업은 추가하지 않았다.

## 채점 기준

- 분모가 같은 분수의 덧셈·뺄셈, 받아올림/받아내림, 자연수에서 빼기, 생활 문장제, 빈칸 추론, 오개념 판단
- 동일한 값의 약분 전/후 분수·가분수·대분수는 정답 인정. 단, 10번은 ‘대분수로 나타내기’이므로 대분수 형식 요구
- 4번과 25번은 정답과 원리를 선택하는 자동 채점 문항. 자유 서술 수동 채점은 없음
- 최종 제출하려면 25문항을 모두 배달(저장)해야 함. 배달하지 않은 수정 초안이 있으면 최종 제출을 막고 해당 문항으로 이동
- 교사는 미제출 상태를 확인하는 명시적 마감 확인 후 강제 채점 가능. 저장된 답안만 채점하고 빈 답안은 오답 처리
- 미입장 번호는 ‘미입장’으로 표기하며 0점/평균에 포함하지 않음
- 시간/토핑/애니메이션은 점수에 영향을 주지 않음. 코인·방 장식 등 운영 경제 보상은 추가하지 않음

## PDF

‘결과받기’는 인쇄창 없이 PDF 파일을 바로 내려받는다. 학급 요약, 학생별 점수·정답 수·제출 상태·오답 번호, 미입장 학생, 25문항 전체 오답률·빈 답안 수·정답·풀이를 포함한다.

한글 폰트 누락을 피하려고 브라우저 Canvas에서 A4 2배 해상도로 그린 페이지를 PDF에 넣는다. 오프라인 PDF 뷰어에서도 한글이 보이며, 텍스트 선택·검색은 지원하지 않는다. PDF 생성 자체에는 외부 라이브러리를 호출하지 않는다. 화면 폰트는 Google Fonts를 사용하고, 연결이 없으면 시스템 한글 폰트로 대체한다.

`docs/product/pizza-assessment/sample-report.pdf`와 PNG는 합성 학생 데이터로 만든 검증 산출물이다.

## 로컬 실행 및 검사

```sh
# 터미널 1: 실제 운영 서비스에 접속하지 않는 demo 프로젝트
firebase emulators:start --project demo-dj48-rules --only firestore,functions

# 터미널 2: Firebase SDK 경로도 로컬 node_modules로 제공
node scripts/smoke/serve-pizza-assessment.js

# 접속: http://127.0.0.1:5324/pizza-assessment/?emulator=1
npm run test:pizza
FIRESTORE_EMULATOR_HOST=127.0.0.1:8181 node tests/pizza-assessment/online.test.js
node scripts/smoke/pizza-assessment-browser.js

# 위 에뮬레이터 종료 후 저장소 전체 검사
npm run check
```

검증 범위: 25문항 독립 정답 계산, 동치 분수, 형식 검증, 동시 입장, 교사 권한, 타 학생 데이터 차단, 정답 비공개, 수정/제출/채점 경쟁 제어, 미제출·미입장 계산, 입장 초기화, 만료, 기존 문항 스냅샷, 실제 별도 브라우저들의 채점 전달, 25문항 입력, 초안/새로고침 복구, 실제 굽기·포장·배달 상태, 학생 피드백, 직접 PDF 다운로드, 모바일 넘침 확인.

## 운영 반영 상태

아직 배포하지 않았다. 실제 학생 데이터, 기존 회원, 운영 설정을 변경하지 않았다.

2026-09-16 검증 완료: `npm run check` 전체 통과(기존 Firestore·Storage Rules와 운영 공개 화면 읽기 smoke 포함), 피자 전용 domain/Firestore emulator/다중 브라우저 smoke 통과. 새로 생성한 PDF 5쪽 전부를 Poppler로 렌더링하여 한글·배치·쪽 나눔을 확인했다. 검사 로그는 `/private/tmp/pizza-full-check.log`에 있으며 임시 파일이므로 장기 보관 대상은 아니다. 로컬 Functions는 설치된 Node 26에서 실행됐고, 운영 Functions 선언 런타임은 기존 Node 22를 유지했다.

운영에 필요한 신규 반영 대상은 `public/pizza-assessment/**`와 Functions export `pizzaAssessmentAction`, 해당 `functions/pizza-assessment/**` 모듈이다. 총괄 관리자 진입 링크는 `public/js/features/admin-render.js`와 재생성한 앱 번들에 포함한다. 별도 Firestore 규칙·인덱스·Auth 제공자 설정은 필요하지 않다. 총괄 관리자 상세는 `PIZZA_SUPER_ADMIN_2026-09-16.md`를 따른다.

현재 작업트리에 다른 기능의 미커밋 변경이 많으므로 운영 반영을 승인받더라도 저장소 전체를 그대로 일괄 배포하지 않는다. 운영 Hosting 버전과 함수 소스를 대조하고 피자 평가 파일/함수만 포함한 검토 가능한 배포 묶음을 구성해야 한다. `AGENTS.md`의 요청 없는 배포 금지에 따라 배포 전 사용자 확인을 받는다.

배포 후 예상 경로: `https://dj48-quiztown-firebase.web.app/pizza-assessment/` (현재 사용 가능한 공개 링크가 아님).

이미지: 기본 내장 image_gen으로 제작한 `public/pizza-assessment/assets/kitchen.png`. 프롬프트 원문은 `docs/product/pizza-assessment/image-prompt.json`. 분할·토핑 피자는 정확한 등분과 상호작용을 위해 SVG로 구현했다.

## 피자 이미지 개선 (2026-09-16 후속)

평평한 SVG 피자 바탕을 투명 배경의 새 화덕 피자 이미지 `public/pizza-assessment/assets/pizza-baked-v2.png`로 교체했다. 첫 화면과 게임 조리대에 동일하게 적용했다. 녹은 치즈, 구운 토마토, 부풀고 노릇한 도우 질감은 내장 image_gen으로 생성했고 원문 프롬프트는 `docs/product/pizza-assessment/pizza-v2-prompt.json`에 보관했다. 기존 배경과 새 피자 이미지를 직접 편집하거나 합성한 파일은 만들지 않았다.

정확한 등분 경계와 클릭 영역은 이미지 위 SVG로 유지한다. 토핑은 토마토·바질·치즈별로 다른 형태를 사용하고 김이 올라오는 효과를 추가했다. 문법 검사, 4~10등분 렌더링/클릭 영역 수 검사, 실제 미리보기 새로고침·시각 확인을 완료했다. 평가·채점 코드는 변경하지 않았으며 기존 01~07 PNG는 최초 구현 검증 시점 이미지다.
