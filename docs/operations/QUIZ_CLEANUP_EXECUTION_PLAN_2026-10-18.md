# 퀴즈 함수·데이터 정리 단계별 실행 정본

기준일: 2026-10-18 KST. 사용자 지시: 단계적인 목표를 문서화하고 이 문서에 따라 엄격히 수행.
조사 근거: [정리 검토 보고서](QUIZ_CLEANUP_REVIEW_2026-10-18.md).

## 목표와 실행 규칙

사용 중인 데이터·보상·랭킹 의미를 유지하면서 불필요한 읽기부터 줄인다. 단순히 오래되거나 중복처럼 보이는 데이터는 삭제하지 않는다.

- 각 단계는 **근거 확인 → 최소 수정 → 해당 검사 → 결과 기록** 순서로 진행한다. 실패한 단계를 완료로 표시하지 않는다.
- 기존 미커밋 작업을 기준으로 이번 변경만 추적한다. 기준 파일은 [해시 기록](QUIZ_CLEANUP_STAGE_BASELINE_2026-10-18.json)과 `/tmp/quiz-cleanup-stages-20261018/baseline/`에 보존했다. 최종 증빙에는 이번 변경의 독립 diff를 남긴다.
- 학생 데이터 원문을 읽지 않는다. 테스트는 합성 데이터와 `demo-*` 에뮬레이터만 쓴다.
- 최초 실행은 아래 0~4단계의 로컬 구현·검증과 5단계 실행안 준비다. 후속 “이어서 작업 진행” 지시에 따라 5단계의 구형 이벤트 집계 쓰기 중단까지 로컬 적용·검증한다. 운영 데이터 쓰기/삭제, Rules·인덱스 변경, 배포·commit·push는 포함하지 않는다.
- `AGENTS.md`의 “보안 규칙이나 학생 데이터에 영향을 주는 변경은 영향과 검증 방법을 먼저 설명하고 사용자 확인 후 진행한다”에 따라 보상 집계 쓰기 중단은 5단계에서 구체적 영향·검증안을 제시한다.
- 배포 전 전체 `npm run check` 통과가 필요하다. 이번에도 화면/번들 변경을 최종 검증한다. 승인 없는 배포는 하지 않는다.

## 단계 1 — 설정 변경 감시

`public/js/infrastructure/admin-repository.js`에서 `appSettings/seasonEvents`를 감시 목록에서 제외한다. 현재 사용하는 나머지 세 문서와 신선도 비교 형식은 유지한다. 이전 로컬 signature와 한 번 불일치할 수 있으나 정상 새로고침으로 갱신된다. 폴링 주기/알림 정책 변경은 이번 작은 단계에 섞지 않는다.

검사: 실제 저장소 함수의 조회 경로를 기록해 종료 문서 호출 0회와 세 문서 변경 감지를 확인한다.

## 단계 2 — 랭킹 읽기 분리

현재 `rankingSnapshot`은 퀴즈왕 종합 계산용으로 유지하고 새 읽기 액션을 추가한다.

- 개인 과목 기록: 인증 회원 본인의 4개 과목 문서를 직접 읽는다. 타인 ID로 조회를 확대하지 않는다.
- 단일 과목 상위 기록: 선택 과목만 점수 정렬해 필요한 공개 행 수만 읽는다. 숨김 행으로 목록이 모자라면 제한된 페이지로 보충하며 기존 안전 상한을 유지한다.
- 브라우저 개인 기록/과목 게시판에서 해당 액션을 사용한다. 기존 일반/인기 랭킹, 개인 상위 기록 순위 문맥, 퀴즈왕 의미를 유지한다.
- 새 액션이 필요한 프런트 배포는 서버 배포·검증 뒤 진행해야 한다. 실패 시 전체 스캔으로 조용히 되돌아가지 않는다.

검사: 계정 권한·다른 회원 요청 거절·비활성/기능 중지·없는 기록·동점·숨김·상위 N개·0쓰기·비대상 컬렉션 0조회. 새 과목 결과와 기존 집계의 동일한 과목 결과를 비교한다. 종합 집계 캐시/재설계는 정확성 문제를 분리해 후속 단계로 남긴다.

## 단계 3 — 관리자 문제은행 검사

현재 인기 서비스가 Firestore에서 읽는 국기·티니핑·포켓몬 1~9세대를 기본 범위로 한다. 생성형 과목과 정적 아이돌/애니 팩은 기존 로컬 검사 대상임을 관리자에게 표시한다. 과거 문제은행은 명시적 ID 목록의 제한된 요청으로만 읽는다. 인증/전체 관리자 제한은 유지한다.

검사: 기본 검사에서 구형 과목 문제은행 전체 열거 0회, 요청 대상 수 상한, 잘못된 ID 거부, 누락/읽기 실패/문항 상한을 정상 완료로 오인하지 않음. 제한은 삭제가 아니며 보관 데이터는 유지한다.

## 단계 4 — 통합 검증

소스 수정 후 정상 빌드로 번들을 갱신한다. 관련 테스트를 먼저 통과한 뒤 에뮬레이터와 `npm run check`를 실행한다. 환경 제한 또는 기존 실패가 있으면 원인·범위·재현을 구분해 기록하고, 통과하지 않은 검사를 완료로 쓰지 않는다. 이 단계에서는 운영 배포를 하지 않는다.

## 단계 5 — 다음 승인과 정리 순서

1. 구형 `eventQuestProgress` 쓰기 중단: 현재 보상·성장 퀘스트·재지급 방지에 영향 없음을 에뮬레이터로 입증한 변경안을 별도 제시한다.
2. 구형 `dailyUsage` 갱신 중단: 외부/구형 클라이언트 사용 종료를 확인한 뒤 처리한다.
3. 미참조 헬퍼 11개와 종료 시즌 UI: 실제 도달성/테스트/배포 소스 대조 후 기능 단위로 제거한다. 인증·예약·트리거는 참조 수만 보고 제거하지 않는다.
4. 이미지: 현재 이미지 551개는 모두 쓰인다. 식별 품질·출처·기존 진행 중 세션 URL을 보존하는 파생본 전환으로 처리한다.
5. 데이터 삭제: 운영 count/최신 갱신/버전/참조를 읽기 전용으로 좁혀 조사한 뒤 ID별 manifest, 백업·복원 시험, 버전 조건을 갖춰 승인받는다. 보상/중복 방지 원장 일괄 삭제 금지.

## 실행 기록

- 단계 0: 보고서와 현재 소스를 재대조하고 수정 대상 12파일의 바이트 원본·SHA-256을 보존했다. 승인 없는 운영 변경 없음.
- 단계 1: 시즌 문서 감시 제거. 실제 저장소 함수 테스트에서 조회 경로가 기능 설정/외부 활동/공지 3개뿐임을 확인했고 `node tests/infrastructure/admin-repository.test.js` 통과. 폴링 간격과 나머지 signature 처리 유지.
- 단계 2: 읽기 전용 `memberRankings`/`subjectRankings` 액션과 브라우저 연결 구현. 개인 과목 조회는 합성 30명 기준 전체 집계 154문서→본인 4문서+인증/설정 3문서=7문서. 기존 본인 일반/인기 기록 조회는 별도 유지한다. 동점의 기존 ID 순서를 보존하기 위해 경계 점수의 동점 행까지 추가 조회한다. 숨김·동점 합성 30행 검사는 해당 과목 30문서를 읽고 타 과목/퀴즈왕/세션 조회 0회. 동점이 많으면 읽기가 늘 수 있으며 최대 501행에서 중단한다. 단위 검사 5건 및 저장소/유스케이스 검사 통과. `npm run check:subject-online` 통과하여 실제 Firestore에서 기존 전체 스냅샷과 새 개인/과목 결과 일치, 보상/한도/중복 방지 유지 확인. 첫 실행은 로컬 포트 EPERM, 다음 실행은 새 테스트 변수명 오류로 중단했으며 수정 후 전체 에뮬레이터 검사 통과. 로그: `/tmp/quiz-cleanup-stages-20261018/subject-online-final.log`.
- 단계 3: 기본 현재 문제은행 11개만 직접 조회하고 전체 `quizzes` 열거 제거. 보관 범위는 `scope: 'archive', quizIds: [...]` 명시 요청의 최대 5개만 허용한다. 동시 문항 조회 3개 제한, 1,201번째 문항으로 1,200문항 상한 초과를 감지한다. 누락·읽기 실패·잘림은 `complete: false` 및 개별 사유로 표시한다. 권한과 문항 품질 판정은 유지한다. 새 단위 검사 3건과 `npm run check:cleanup-online`의 실제 callable 관리자/학급관리자 권한·범위·보존 검사 통과. 관리자 렌더러 원본도 추가 보존했다. 로그: `/tmp/quiz-cleanup-stages-20261018/admin-online.log`.

- 단계 4: `npm run check` 전체 통과(규칙·도메인·저장소·화면 포함, 과목 2,502 화면 및 자동 종료 시나리오). 이후 최종 서버 동점 보완은 `check:subject-online`, 구형 집계 호출 제거는 `check:cleanup-rewards`, 최종 빌드는 `check:static`으로 추가 검증했다. 최종 서버 보완 이후 전체 장시간 화면 검사를 다시 실행한 것은 아니다. 관리자 부분 완료/보관 범위 화면은 390/1440px에서 별도 검사·시각 확인했다.
- 단계 5: 계속 진행 지시에 따라 구형 집계 헬퍼 호출 두 곳만 제거했다. `check:cleanup-rewards`에서 일반 연습 동시 중복·코인 50/XP 20 한도·권한·기능 중지·생성형 정답·인기 완료 보상·랭킹 완료 재시도·성장 트리거 재시도·현행 퀘스트 수령을 검증했다. 구형 합성 문서의 updateTime 불변 및 전체 구형 문서 수 1개 유지 확인. 나머지 헬퍼/데이터/이미지 삭제를 완료했다는 뜻은 아니며 아래 후속 게이트로 남긴다.

## 최종 증빙과 후속 게이트

후속 실행 순서와 완료 기준은 [6~12단계 후속 계획](QUIZ_CLEANUP_FOLLOWUP_PLAN_2026-10-18.md)을 따른다. 아래 완료 기록은 0~5단계의 로컬 범위이며 운영 반영 완료를 뜻하지 않는다.

- [이번 변경 독립 patch](QUIZ_CLEANUP_LOCAL_CHANGES_2026-10-18.patch): 기존 작업 기준 원본 대비 이번 소스·테스트 변경만 포함. 생성 번들은 제외하고 해시로 기록했다.
- [검증 결과·파일 해시](QUIZ_CLEANUP_VERIFICATION_2026-10-18.json): 통과 로그 요약과 원본 로그 SHA-256.
- [구형 쓰기 변경 영향과 남은 게이트](QUIZ_CLEANUP_NEXT_GATE_2026-10-18.md).
- 운영 반영은 미실행. 새 랭킹 서버 액션을 먼저 배포·검증한 뒤 프런트를 반영해야 한다. 현재 운영 Functions 소스 및 구형 클라이언트 소비 여부를 먼저 대조한다.
