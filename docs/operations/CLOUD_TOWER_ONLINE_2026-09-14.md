# 구름탑 공용 랭킹·실시간 레이스 인계

2026-09-14 · 상태: 사용자 운영 반영 승인 후 Functions·Rules·Hosting 배포 완료.

## 사용자 요청과 구현

공용 랭킹, 실시간 대전, 퀴즈타운 내부 랭킹 탭을 추가했다. 운영 학생 데이터를 조회·수정하지 않고 합성 계정으로 검증했다.

- 구름탑의 ‘온라인 연결’에서 현재 퀴즈타운 로그인을 그대로 사용한다. 새로운 익명 계정을 만들거나 학생 계정을 교체하지 않는다.
- 서버가 `authLinks/{uid}` → `users/{memberUserId}`를 확인한다. authUid가 일치하고 active 상태인 연결 계정만 참여·조회한다. 공개 표시에는 기존 별명만 사용하며 이름·학교·학년·반·번호는 새 기록에 복사하지 않는다.
- 로그인 후 챌린지는 기본적으로 공용 랭킹에 기록한다. 체크를 해제하면 종전 기기 기록 챌린지다. 자유 연습은 랭킹 제외.
- 실시간 레이스는 6자리 방 코드로 2~4명이 참가한다. 모두 준비 완료한 뒤 방장만 출발 가능. 서버에서 5초 뒤의 공통 출발 시각을 발급한다.
- 각자 같은 120초 코스에서 플레이한다. 정답 제출 시 서버가 점수·층·정확도를 계산하고 같은 방 참가자에게 실시간으로 전파한다. 상대 위치와 순위가 화면에 표시된다.
- 중간 탈락한 친구가 있어도 남은 참가자는 계속 진행한다. 모두 종료되면 결과를 표시한다. 같은 점수·정확도·시간이면 공동 1위로 표시한다. 포기자는 정상 종료 참가자 뒤에 배치한다.
- 새로고침·일시 연결 끊김 후 ‘진행 중인 게임으로 돌아가기’에서 같은 방·게임을 복구한다. 현재 게임 연결은 서버의 개인 진행 포인터에서 확인한다.
- 대기방 방장이 나가면 남은 첫 참가자에게 방장을 넘긴다. 대기방 만료는 15분. 진행 중인 방은 고정 시작 시각으로 끝나므로 연결 끊김이 제한 시간을 늘리지 않는다.
- 퀴즈타운 랭킹 광장 **온라인 대전 → 구름탑** 하위 탭에 상위 50개의 서버 확인 최고 기록을 표시한다. 기존 탭 클릭 핸들러를 그대로 사용한다.

## 새 데이터와 접근 범위

| 경로 | 저장 내용 | 클라이언트 접근 |
| --- | --- | --- |
| `cloudTowerRanking/cloud-120-v1/entries/{authUid}` | 별명, 점수, 층, 정확도, 소요 시간, 코스 버전, 정렬 키, 기록 시각 | 활성 연결 계정 읽기, 쓰기 금지 |
| `cloudTowerRooms/{code}` | 참가 authUid·별명·준비·진행·점수·접속 확인 시각·게임 ID, 방 상태·시각 | 활성 연결 계정 중 참가자만 단일 방 읽기, 목록·쓰기 금지 |
| `cloudTowerRuns/{runId}` | 소유 authUid, 서버 시작 시각, 점수 계산 상태, 제출 순번·최근 요청 해시, 종료 상태 | 읽기·쓰기 금지, callable 응답으로 본인 진행만 전달 |
| `cloudTowerPlayers/{authUid}` | 현재 방/게임 ID와 유효 시간 | 읽기·쓰기 금지, 본인 profile callable로 복구 정보 전달 |

모든 새 쓰기는 `cloudTowerAction` 한 서버 함수가 담당한다. 기존 `rankingRecords`, `userRankingSummary`, `quizKingSummary`, 코인, 프로필은 수정하지 않는다. 보안 규칙은 위 새 경로만 추가했다. 복합 인덱스 추가 없이 단일 `sortKey`로 정렬한다. 기존 공개 랭킹 숨김 대상 학생에 대해서는 공용 기록을 생성하지 않는다.

종료된 방과 진행 기록은 보존한다. 이 작업에서는 자동 삭제·마이그레이션·TTL 정책을 추가하지 않았다. 만료는 새 참가·출발을 제한하는 의미다. 연결이 모두 끊겼다면 참가자의 다음 복귀/상태 확인 요청에서 서버가 원래 마감 시각을 기준으로 종료를 확정한다.

## 서버 계산과 전송

- 고정 코스와 점수 계산은 `public/cloud-tower/domain.js`와 Functions 내부 미러가 동일하며 테스트에서 파일 전체 일치를 검사한다. 코스 수정 시 양쪽을 함께 갱신한다.
- 문장 완성마다 입력 변화 목록을 전송한다. 서버는 순서, 정확한 목표 문장, 길이·개수 상한, 제출 간격, 시작·마감 시각을 검사한 뒤 도메인을 재실행한다. 클라이언트가 보낸 점수·층은 받지 않는다.
- 같은 순번·동일 요청의 재전송은 이전 성공 결과를 반환한다. 순번 건너뛰기, 다른 내용의 동일 순번은 거절한다. 중복 점수 없음.
- raw 입력 변화 목록은 문서에 저장하지 않는다. 최신 제출의 해시와 누적 수치만 보존한다.
- 입력 목록은 클라이언트가 제공하므로 봇·매크로 사용을 완전히 판별하는 장치는 아니다. 코인·상품 지급은 연결하지 않았다.
- 서버 종료 확인 전에는 공용 기록 저장 완료로 표시하지 않는다. 실패 시 ‘서버 기록 다시 확인’ 버튼을 제공한다.
- 방은 Firestore 문서 리스너로 갱신하고 5초마다 참가자 상태와 마감을 확인한다. 방을 나가면 리스너·상태 확인을 종료하고, 늦게 도착한 이전 방 응답은 무시한다.

## 운영 적용 범위와 승인

로컬 구현 완료 후 사용자가 “배포된 상태인건가? 운영사이트에 반영해봐”라고 승인했다. 아래 범위로 운영 반영했다.

1. Functions의 **cloudTowerAction만** 배포. `functions/index.js`에는 다른 작업의 하우징 변경도 있으므로 전체 함수 배포를 하지 않는다.
2. Firestore Rules의 구름탑 경로 추가분을 운영 규칙과 대조한 뒤 적용. 기존 학생 컬렉션 권한 변경 없음.
3. Hosting: `public/cloud-tower/**`, `public/js/ct-ranking-plaza.js`, 메인의 스크립트 태그 추가, 온라인 대전 목록 카드 문구. 메인/메뉴에는 다른 작업 변경이 섞여 있으므로 운영본 기준으로 이번 변경만 추려서 배포 준비한다.
4. 게시 후 공개 파일 응답과 정적 일치 확인. 실제 학생 계정을 자동으로 생성하거나 시험 기록을 운영에 쓰지 않는다.

온라인 미리보기는 `?emulator=1`을 붙인 로컬 demo 환경에서만 사용하며, 테스트 합성 계정은 운영과 무관하다. 기본 Python 정적 미리보기는 SDK/서버가 없으므로 오프라인 플레이만 가능하다.
