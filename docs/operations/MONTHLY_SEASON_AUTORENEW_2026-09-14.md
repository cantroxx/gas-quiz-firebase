# 월간 시즌 자동 전환

## 구현 상태

2026-09-14 로컬 구현·검증 후 사용자 배포 승인으로 운영 반영 완료. 기존 시즌 설정의 비활성 상태는 유지했다.

관리자 시즌 이벤트 입력에 **매월 자동 전환** 옵션을 추가했다. 월간 시즌의 `autoRenew: true`를 저장하면 서버가 한국시간 현재 월을 기준으로 기간을 계산한다. 지난달 값을 저장한 뒤에도 다음 달에 다시 수정할 필요가 없다. 스케줄 작업이나 학생 기록 삭제 없이 날짜 경계에 따라 같은 결과를 산출한다.

- 매월 1일 00:00 Asia/Seoul부터 새 월의 기록으로 시즌 순위를 계산한다.
- 시즌 제목과 대상 퀴즈는 유지한다. 월별 무작위 주제 변경과 자동 보상은 포함하지 않는다.
- 고정 월 지정과 주간 시즌은 기존 동작을 유지한다. 기존 문서에 `autoRenew`가 없으면 고정 월을 임의로 바꾸지 않는다.
- 랭킹 화면을 계속 열어둔 경우 월 변경을 최대 60초 내 감지해 다시 읽는다. 숨긴 탭으로 복귀할 때도 확인한다.
- `rankingRecords`, `userRankingSummary`, `quizKingSummary` 기록은 수정·삭제하지 않는다.

## 조회 보완

기존 시즌 조회는 카테고리별 기록을 기간 조건 없이 최대 80건 이상 읽은 뒤 화면에서 날짜를 거르는 구조였다. 새 조회는 `categoryKey`와 `recordedAt` 기간을 조건으로 읽으며, 200건씩 페이지를 순회한다. 과거 기록이 많거나 해당 월 기록이 200건을 넘어도 누락하지 않는다.

필요한 복합 인덱스는 `rankingRecords(categoryKey ASC, recordedAt DESC)`이며 `firestore.indexes.json`에 추가했다. 운영에서는 해당 인덱스가 준비된 뒤 새 프런트엔드를 공개해야 한다.

시즌 화면 모델의 `rows`와 `sourceRows` 모두 시즌 기간으로 한정한다. 일반 랭킹의 저장 경로와 랭킹 모드 판정은 변경하지 않았다.

## 운영 설정 확인

`appSettings/seasonEvents`의 제목·기간·대상 퀴즈만 읽기 전용으로 확인했다.

- 독서왕 시즌: 월간, 2026-07 고정, `gmo`·`time_store`, 비활성.
- 삼국시대 탐험 주간: 2026-06-29~07-05, `samgukji`·`ancient-history`, 비활성.

따라서 기능을 배포하는 것과 실제 시즌을 활성화하는 것은 별도 조치다. 현재 비활성 상태는 유지했다. 월간 시즌의 자동 운영을 시작하려면 활성과 매월 자동 전환을 선택해 저장해야 한다.

## 검증

- `npm run check` 통과: 전체 기존 검사와 새 월간 시즌·Firestore Emulator 조회 검증 포함.
- 마지막 화면 모델 보완 뒤 해당 단위 테스트와 `npm run check:static` 재통과.
- 월·연도 경계, 윤년, 고정 월 호환, 원본 설정 불변 검증.
- Emulator에서 200건 초과 데이터, 페이지 순회, 한국시간 월 시작·끝 경계, 숨김 회원 제외, 비활성 이벤트, 다음 달 전환, 이전 기록 보존 검증.
- 관리자 브라우저에서 자동 전환 선택 시 고정 월 입력 잠금, 선택 해제 시 입력 복원, 월간·주간 변경 및 저장 payload 검증.
