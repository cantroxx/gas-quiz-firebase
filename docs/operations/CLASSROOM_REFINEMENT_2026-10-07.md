## 실제 수정

### 변경 없는 상품 목록의 DOM 보존

기존 전체 모델 렌더는 현재 홈을 보고 있어도 60개 상품의 카드·상세·이벤트 연결을 매번 다시 만들었다. 데이터가 동일한 한 번의 호출에서도 상품 grid의 childList 변경 기록이 75개이고 첫 카드 노드가 교체됐다. 이 구간은 기존 탭 전환·상품 선택 최적화와 별개였다.

`renderClassroomShopCards`가 실제 표시 입력의 스냅샷을 비교하고, 동일하면 살아 있는 목록과 포커스를 보존하도록 수정했다. class/member/teacher, 상품 DTO 전체, 정규화 이미지 URL, 포인트·DJ코인 잔액, 관련 구매 소유 상태를 포함한다. 인플레이스 상품 가격 수정도 감지한다. 서버 응답이나 데이터 조회를 캐시하는 변경은 아니다. 입력이 바뀌면 기존 전체 갱신을 그대로 수행한다.

수정 후 동일 입력의 상품 DOM 변경 기록은 0개이고 첫 카드 노드·포커스가 유지된다. 이미지 교체·CSS·탭 구조를 바꾸기 전 DOM 보존만 적용한 분리 실험에서도 전체 중앙값 36.7→28.8ms, JS 27.6→19.7ms였다. 이 단일 실험은 인과 확인용이며 아래 반복 측정을 대신하지 않는다.

### 비용 구분

- **DOM/JS:** 75→0 mutation 기록과 노드 동일성, DOM 보존만 적용한 분리 실험으로 변경 없는 목록 재생성을 확인했다. 실제 값 변경 시에는 다시 만든다.
- **계측:** 빈 `performance.now`/깨끗한 bounding rect 호출의 중앙값은 0ms, 최대 전 0.3ms/후 0ms였다(타이머 분해능 이하 포함). 추적을 켠 수치는 주요 성능표에서 제외했다.
- **스타일/레이아웃:** 별도 20회 프레임 간 trace에서 양쪽 모두 UpdateLayoutTree와 Layout 각 20회. 강제 레이아웃 구간 중앙값은 8.45→9.30ms로 개선을 확인하지 못했다. 새 CSS가 무조건 빨라졌다는 주장은 하지 않는다. JS는 해당 진단에서 28.25→22.10ms였다.
- **이미지 디코딩:** 진단에서 로컬 이미지를 사전 로드·decode한 warm 조건에도 위 차이가 남았다. 수집된 trace에는 이미지 decode 이벤트가 없었다. 이것은 최초 decode 비용이 0이라는 증거가 아니며, 실제 초기 로딩 개선은 측정하지 않았다. 새 단순 SVG는 큰 PNG 다운로드를 추가하지 않는다.
- **이벤트/구독:** GC 후 이벤트 리스너 수는 전 262→262, 후 263→263으로 20회 반복 후 늘지 않았다. 추가 1개는 새 경제 메뉴 키보드 위임이다. 기존 상품 미디어 쿼리 listener는 재생성 때 AbortController로 해제하며, 동일 목록 보존 시 다시 등록하지 않는다. 이번 변경에 API/실시간 구독 추가 없음.
- **숨겨진 탭:** 시작 버전은 전체 모델을 넘기면 숨겨진 탭까지 생성했다. 이번 실행 중 다른 작업에서 activeTab에 따른 렌더/조회 분리가 추가됐고 이를 보존했다. 이 보고서의 전후 벤치마크는 양쪽 모두 activeTab을 전달하지 않는 전체 모델 경로로 비교해 그 별도 최적화의 효과를 이번 수치에 포함하지 않는다.

### 측정하지 않은 것

로그인된 운영 교실의 서버 응답, 첫 진입 완료 시간, 학교 네트워크 전송량, 실제 휴대전화의 스크롤 FPS는 측정하지 않았다. `getClassroomEconomyBoard`에는 상태 저장 경로가 있으므로 학생 계정으로 호출하지 않았다. mock 지연과 Emulator 검사를 운영 속도로 해석하지 않는다. synchronous scroll 측정은 0ms 부근으로 분해능이 부족해 스크롤 개선의 근거로 쓰지 않는다.

잔액·상품 내용 등이 바뀌는 실제 갱신은 전체 목록을 다시 생성하며 이번 측정에서 속도 개선이 확인되지 않았다. CSS/레이아웃 비용도 줄였다고 판단할 수 없다. 실제 서버 응답·로그인 첫 진입·휴대전화 FPS는 아직 검증하지 않았다. 이 세 가지를 포함한 전체 성능 개선 완료로 표현하지 않는다.
